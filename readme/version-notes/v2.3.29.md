## v2.3.29 — Dashboard Hybrid Query (session TEMP tables) *(21 Jul 2026)*

---

### Dashboard Builder — Hybrid multi-database widgets

**Problem:**
- Dashboard widgets needed data from **two databases**: external SQL Server (ERP / HRMS) and internal PostgreSQL.
- An earlier staging approach used shared / durable temporary-style tables across pool connections, which risked isolation issues, orphaned tables, and unclear builder UX between “preview ERP” and “merge with Postgres”.

**Cause:**
- PostgreSQL `TEMP` tables are **session-scoped**. They cannot survive across separate HTTP requests when connections are returned to the pool.
- Holding a pool connection open between Step 1 and Step 2 would block concurrency under multi-user load.
- Publish payloads that omitted `chart_config` (including `hybrid_mssql_query`) caused live loads to run plain Postgres SQL still containing `{{temp_erp_data}}`, producing query failures after publish.

**Fix:**
- Introduced a dedicated **Hybrid Query Engine** that:
  1. Fetches the full external MSSQL result (via IMS).
  2. Opens **one** PostgreSQL transaction.
  3. Creates `CREATE TEMP TABLE    (…) ON COMMIT DROP`, inserts all ERP rows, runs the merge SQL.
  4. Commits — TEMP is dropped automatically (also on rollback).
- Builder **Step 1** only previews ERP (columns + sample); it does **not** create TEMP.
- Builder **Step 2** / publish / live dashboard re-fetches ERP and performs TEMP + merge in a single request.
- Publish JSON now persists hybrid `chart_config` fields so live execution stays on the hybrid path.
- Merge SQL uses `{{temp_erp_data}}` as the ERP-side placeholder; no artificial row truncate on hybrid results (PG statement timeout: 120s).
- Concurrent users each get an isolated session TEMP (same table name is safe).

**Flow:**
1. Widget → Database → **Hybrid** → choose ERP/HRMS source → write MSSQL query → **Preview ERP query**.
2. Write PostgreSQL merge SQL using `{{temp_erp_data}}` → **Run merge query**.
3. **Save / Publish** — config stored; each live open re-runs MSSQL → TEMP → merge → drop.

**Reflects:**
- Dashboard Builder → Property Panel → Hybrid Step 1 / Step 2 labels and placeholder guidance
- Published hybrid widgets on live dashboards
- API: `POST /dashboard/widgets/hybrid-preview`

### Dashboard Builder — Table search / export action header

**Problem:**
- Table search and export controls stacked as large full-width rows and were hard to align consistently.

**Fix:**
- Compact single-row action header (search + export), right-aligned by default; export keeps solid blue styling with a right-aligned dropdown menu.
- Builder controls for search **align** (`left` | `center` | `right` | `full`) and **width** (160–600px; ignored when Full).

**Files:**
- `frontend/src/features/dashboard-builder/components/WidgetRenderer.js`
- `frontend/src/features/dashboard-builder/utils/tableToolbar.js`
- `frontend/src/core/components/common/ExportMenu.js` — `menuAlign` support
