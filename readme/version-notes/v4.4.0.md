## User attributes

### Purpose

Tags such as Sales Person or Packing Team sit beside role, department, and designation. Planned use: notification targeting (SMS / WhatsApp / PWA). Attribute permissions are **not** in this release.

### Database

| Item | Notes |
|------|--------|
| `mst_attributes` | Master names; deleted name can be re-added and revives same row |
| `mst_users.attribute_ids` | Full list replaced on save; existing DBs get column via `patchCol` on boot |

### User save — `attributes` body

| Value | Result |
|-------|--------|
| Omitted on update | Links unchanged |
| `[]` | Clears all |
| `[{ id }]` | Link existing |
| `[{ name }]` | Create or revive by name, then link |

Invalid shape → `400 Invalid attributes`.

### User form (frontend)

- `CreatableMultiSelect` + `UserModal` — same row as Department / Designation.
- Shown only when role is **not** `super_admin` or `admin` (same as dept/desig).

### Attribute helper (IMS style)

`POST …/attributes/helper` — caller sends `permission_module` + `permission_action`. Allowed today: **users** + view / add / edit / authorize. If the pair matches, `accessControl` runs on that module action; else `403`.

Route: `helperAccess("attributes")` — allowed pages defined in `HELPERS.attributes` inside `helperViews.js` (same pattern as `departments` / `designations`).

### Core `triggers.table.js`

Called from `initDB` after tables exist. Defines `set_updated_at()` and `BEFORE UPDATE` triggers on core masters (including `mst_attributes`) so `updated_at` updates on every row change without setting it in every query. Does not set `updated_by`.

| Triggers / boot | `tables/db/triggers.table.js`, `initDB.js` |

## RM Store — Store In receive (Unassigned pending)

**Goal:** Operators receive shop-floor returns into Unassigned Area from the **Store In** screen only, using Store In permissions — not from IPR Register.

| Route | Permission |
|-------|------------|
| `POST …/in-process-requests/complete-store-in` | `rm_inventory_inwards` **add** only (`storeInReceiver`) |
| `POST …/pending-store-in` | IPR **view** **or** Store In **view** / **add** (`storeInReader`) |
| `POST …/pending-store-in/get` | Same as pending list (single row for Receive modal) |

**Frontend**

| Page | Behaviour |
|------|-----------|
| `inventory-inward/Page.js` | Receive pending store-in on Unassigned tab; toolbar + hotkeys when row is receivable |
| `ReceivePendingStoreInModal.js` | Loads row via `pending-store-in/get`; submits `complete-store-in` |
| IPR (`InProcessRequestModal.js`, Register) | **No** Receive UI — copy still explains “Receive in Unassigned → Store In” |

Receive updates **same** coil qty and moves it back to Unassigned (no duplicate coil row).

## RM Store — IPR consume reassign vs Store In

When partial consume uses **reassign** (`reassign: true` with `remaining_qty > 0`), balance moves to the **target job card on shop floor** — it does **not** queue Unassigned Store In.

| Layer | Rule |
|-------|------|
| `resolveConsumeDownstream` | Reassign balance → downstream **consumed** (not `PENDING_STORE_IN`) |
| `hasReassignShopFloorBalance` | Detects reassign lines with remaining qty |
| Pending queue SQL (`pendingStoreInQueue`) | Excludes consume IPRs that still have reassign shop-floor balance |
| `findPendingStoreInForCoil` | Same exclusion when resolving coil’s pending IPR |
| `getPendingStoreInById` / `completeStoreInCtrl` | `400` if reassign balance — not receivable |

Coil transaction logs use types such as **`ipr_reassign`** / revert; approve delete can pass `reassign_revert` in payload.

**Job card on IPR (normal flow):** No JC dropdown on IPR — scan reads `pjobcardno` / `macname` from coil (Issue Request → Store Out). Reassign JC pick UI remains off in product; backend validation (`assertConsumeReassignRules`) still applies when reassign lines are saved.

Full path map: [../app-flow/JOB_CARD_AND_MACHINE.md](../app-flow/JOB_CARD_AND_MACHINE.md)

```
IMS prdrunjc.macname → IssueRequestModal (select JC) → Store Out on coil → IPR scan (no JC select)
```

| Topic | File |
|-------|------|
| Issue JC → machine | `issue-request/IssueRequestModal.js` — `handleJcChange` |
| One machine = one JC | `ISSUE_REQUEST_MACHINE_JOB_CARD_LOCK`; BE `findMachineShopFloorJobCardConflicts` |
| IPR scan / shop floor | `InProcessRequestModal.js`, `saMinusInventory.js` — `isIssuedToShopFloor` |

## RM Store — Coil Finder FG and layout

**Helper:** `POST /api/rmstore/coils/helper` with `finder: true` and caller `permission_module` / `permission_action` (same pattern as other RM helpers).

**Enrich order in `loadCoilRow` (finder mode)**

1. `findCoilByUid` once  
2. Parallel: `findPendingStoreInForCoil`, `enrichCoilRmSpec` (patch `{ rm_spec_code, rm_spec_label }`), `loadCoilFinderScreenData`  
3. `enrichCoilFgFromProductionMaster` — store/rack FG from Item RM Master when coil has no FG yet  
4. `enrichCoilFgForReassign` — shop floor + reassign wire splits  

| Source | FG meaning |
|--------|------------|
| **Store / rack** | Approved production mapping for RM wire (`findProductionFgForRmWire`, one FG) |
| **Shop floor** | Job card FG from issue-request join (`findJobCardFgByPjobcardno`) |
| **Reassign** | `fg_wire_splits`: wire **on job**, **cut** on source JC, **balance** on target JC |

**UI (`CoilFinderDrawer.js`)**

- “This coil” card — primary FG from `partitionFgWireSplits` (balance split preferred when present)  
- Additional FG cards for other splits  
- **Placement** in `CoilFinderPlacementSection.js` (location / zone separate from FG)  
- QC, documents, journey below Full record grid  

**Display:** `formatPjobcardnoDisplay` in `coilTableVisuals.js` avoids duplicated `JC` prefix (e.g. not `JC JC-123`).

**Full record grid**

- Server finder payload returns `details: []` — grid built in FE from `coilFinderFullRecordConfig.js` (`show` / order per field).  
- `coilFinderData.js` — `buildCoilFinderDetailRowsFromConfig`.

**Journey**

- `formatReassignJourneyLine` — e.g. `JC-A → JC-B · wire cut · balance` for `ipr_reassign` events  
- Raw `reassign_lines` JSON not dumped in journey text  

**Finder bundle**

- `loadCoilFinderScreenData.js` — QC/docs via `loadCoilFinderReportData(uid, existingCoil)` (no second coil read)  
- Transaction journey limit **500**, sticker download logs **200**, `skipCount: true` on coil tx list  
- If report leg fails, coil row still returns; `finder` may be empty object  

**Permissions:** Open Coil Finder only when user has `rm_coils` **view** (Coils list and Store In list).

## RM Store — master lists (no hidden old rows)

List endpoints for **Item RM Master**, **RM Spec Master**, and **Store Location Master** remove `from_date` / `to_date` from server list filters so date defaults do not hide older authorized rows.

Frontend pages use `fetchAllListPages` + client search / status filter (same idea as [LIST-PAGE-CLIENT-FILTER.md](../app-flow/LIST-PAGE-CLIENT-FILTER.md)).

| Controller | Change |
|------------|--------|
| `productionMaster.controller.js` | Delete date keys from `listFilters` on list |
| `specMaster.controller.js` | Same |
| `storeLocationMaster.controller.js` | Same |

FE: `modules/master/production/Page.js`, RM Spec and Store Location master pages.

## Deploy / test checklist

1. Restart backend; rebuild frontend or hard refresh.  
2. **Store In:** Unassigned row with pending store-in → Receive works with **add** permission; user without add gets blocked.  
3. **IPR:** No Receive button on register/modal; consume partial **without** reassign still queues receive; **with** reassign balance absent from pending list and API receive returns clear error.  
4. **Coil Finder:** Stored coil shows master FG; shop-floor coil shows JC FG; reassign coil shows split cards and journey reassign line.  
5. **RM masters:** Scroll/search finds old production / spec / location rows not cut off by list date filter.  
6. **Helper:** Coil finder helper returns in reasonable time on a coil with long history (journey capped).
