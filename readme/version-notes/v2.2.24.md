### Store Out — Inventory Out approval

**Problem:**
- Submitting an **Inventory Out** entry immediately marked it **AUTHORIZED** and reduced stock in the same step.
- There was no Super Admin / authorize step before inventory reflected the change.

**Cause:**
- Inventory Out was treated as auto-authorized, unlike Forwarding Note Out, which uses draft → pending → authorize.
- Business required users with the special permission to create entries, but stock should update only after an authorized user approves.

**Fix:**
- Submit creates a **PENDING** entry; stock is not changed until approval.
- Super Admin or a user with `out_entry` → **authorize** approves from the Store Out list → entry becomes **AUTHORIZED** and stock is applied.
- The `ims.inventory_out` special permission gate on create is unchanged.
- Packing Area and QC Area remain auto-authorized on submit.

**Flow:**
1. User (with `inventory_out` permission) → scan boxes + submit → **PENDING**
2. Admin / Super Admin (with authorize) → **Approve** → stock reflects in inventory

**Reflects:**
- Store Out list → Inventory Out shows **PENDING** until approved
- Approve button enabled for pending Inventory Out rows
- Inventory unchanged until authorization

**Files:**
- `backend/src/apps/ims/utils/out-entry/outEntryTypes.js` — removed Inventory Out from auto-authorized types
- `backend/src/apps/ims/controllers/outEntry.controller.js` — create as pending; update with approval workflow

- `frontend/src/features/apps/ims/utils/outEntryTypes.js` — same helper; enables Approve on list
- `frontend/src/features/apps/ims/components/out-entry/OutEntryModal.js` — submit pending, approve mode, UI copy


### Schedule Item Wise — Schedule Qty, Balance Qty, Dispatch Qty

**Problem:**
- **Schedule Item Wise** showed only **Total Qty** and **FG Stock**.
- After partial Forwarding Notes for the same schedule line, users could not see how much had been dispatched and how much remained.
- **Today Dispatch Plan** showed full schedule quantity in the **Qty** column instead of the remaining balance.

**Cause:**
- Multiple Forwarding Notes can be created for the same **Sch No + Item** (partial dispatch).
- The UI did not aggregate dispatched quantity from existing forwarding notes or compute the remaining balance.

**Fix:**
- Renamed **Total Qty** → **Schedule Qty** (original scheduled quantity).
- Added two columns after **FG Stock**:
  - **Dispatch Qty** — sum of `total_qty` on all Forwarding Note items for the same Sch No + Item
  - **Balance Qty** — `Schedule Qty − Dispatch Qty` (remaining to dispatch)
- **Today Dispatch Plan:** renamed **Qty** → **Balance Qty**; row highlighting uses balance vs FG stock.
- New Forwarding Note from dispatch plan prefills item quantity from **balance**, not full schedule qty.
- **New** from dispatch plan is offered only when balance > 0 and FG stock > 0.

**Example:**
- Schedule: 20,000 → first FN: 8,000 → Dispatch: 8,000 | Balance: 12,000  
- Second FN defaults to 12,000.

**Reflects:**
- Schedule Planning → Schedule Item Wise: Schedule / Balance / Dispatch columns
- Forwarding Note → Today Dispatch Plan: Balance Qty column
- Forwarding Note modal: prefill from remaining balance

**Files:**
- `backend/src/apps/ims/utils/schedule-planning/schedulePlanDb.js` — load dispatched qty by Sch No + Item from forwarding notes
- `backend/src/apps/ims/utils/schedule-planning/schedulePlanService.js` — enrich rows with `schedule_qty`, `dispatch_qty`, `balance_qty`

- `frontend/src/features/apps/ims/components/schedule-planning/schedulePlanningColumns.js` — column rename and new columns
- `frontend/src/features/apps/ims/components/forwarding-note/TodayDispatchPlanTab.js` — Balance Qty column
- `frontend/src/features/apps/ims/components/forwarding-note/ForwardingPage.js` — New FN filter (balance > 0)
- `frontend/src/features/apps/ims/components/forwarding-note/ForwardingModal.js` — prefill from balance qty

### Dashboard Builder — Separate laptop / phone layouts

**Problem:**
- A dashboard designed on laptop also showed the **laptop side-by-side layout** on phone.
- Saving or publishing using only the laptop builder copied desktop coordinates into `mobile_layout`.
- Widgets inside containers also appeared multi-column on phone, like desktop.
- Adding a new widget on laptop did not update the phone layout.

**Cause:**
- Multiple fallbacks copied `layout` when `mobile_layout` was missing.
- `nested_layout` was used as-is when `mobile_nested_layout` was missing.
- Desktop coordinates were saved at publish time even when the phone layout was never customized.
- `syncNestedChildLayoutsFromContainers` copied desktop nested coordinates into each child's `mobileLayout`.

**Logic (how it works now):**

| Mode | What is shown | Data source |
|------|---------------|-------------|
| **Laptop builder** | Desktop grid (`layout`, `nestedLayout`) | `builderDeviceMode = desktop` |
| **Phone builder** | Phone grid (`mobileLayout`, `mobileNestedLayout`) | `builderDeviceMode = mobile` |
| **Published — wide screen** | Laptop layout | `resolvePublishedDesktopLayout` |
| **Published — phone (≤767px)** | Phone layout | `resolvePublishedPhoneLayout` + `isPhoneView` |

**When phone layout is saved vs auto-stacked:**
- If the user designed a separate layout in the phone builder (`hasCustomTopLevelMobileLayout` = true) → saved `mobile_layout` is used.
- If the phone layout was never customized (or is a copy of desktop) → `stackLayoutForPhone` builds a **full-width vertical stack** (each widget `x:0`, `w:12`).
- Same rule for container nested layouts: without custom `mobile_nested_layout`, `stackNestedLayoutForPhone` stacks inner widgets.
- Helper: `resolvePhoneNestedLayoutForDisplay` — compares desktop vs mobile nested layouts and picks the correct one.

**Save / publish flow:**
1. On draft save or publish, `layout` and `mobile_layout` are stored separately in JSON.
2. If phone is not customized, `mobile_layout` is auto-generated (stack) at publish time — laptop coordinates are not copied.
3. `publishMobileLayout` filters only top-level widgets (no orphan slots).
4. Adding a widget on laptop → `mobileLayout` is also updated via `mergeMobileLayoutFromDesktop`.
5. First phone builder toggle → `initMobileLayoutFromDesktop` / `stackNestedLayoutForPhone` for nested.

**Container height (phone live view):**
- On unlocked containers, `fitPhoneContainerGridHeight` — no extra empty space beyond saved height; height follows nested content.

**Reflects:**
- Builder: Laptop icon = laptop layout; Phone icon = phone layout (separate editing).
- Live dashboard: wide browser = laptop; mobile width = phone stack.
- Old dashboards with incorrect `mobile_layout` — **re-publish once** to apply the new logic.

**Files:**
- `frontend/src/features/dashboard-builder/utils/dashboardLayoutEngine.js`
  - `resolvePublishedPhoneLayout` — use custom mobile; otherwise stack from desktop
  - `resolvePhoneNestedLayoutForDisplay` — phone nested stack vs saved mobile
  - `buildNestedLayoutForLiveDisplay` — phone nested fallback fix
  - `stackLayoutForPhone`, `stackNestedLayoutForPhone` — vertical full-width layout
  - `hasCustomTopLevelMobileLayout`, `hasCustomMobileNestedLayout` — detect customization
  - `fitPhoneContainerGridHeight`, `phoneContainerAutoGridHeight` — phone container height
  - `syncNestedChildLayoutsFromContainers` — no longer copies desktop nested into `mobileLayout`

- `frontend/src/features/dashboard-builder/components/DashboardBuilder.js`
  - Builder device mode switch (laptop / phone)
  - `buildDashboardJsonPayload` — phone stack + nested resolve on publish
  - `readOnlyPhoneLayout` — live phone view layout
  - `getContainerNestedMobileSource` — phone nested only when customized or stacked
  - Load widgets: empty `mobileLayout` when not customized (seed on phone switch)
  - `addWidget` — updates `mobileLayout` when adding on laptop

- `frontend/src/features/dashboard-builder/components/WidgetRenderer.js`
  - `resolveContainerNestedLayout` — nested stack in phone mode
  - `isPhoneMode` — table compact / responsive sizing

### Dashboard Builder — Table widget (search, sort, colors, responsive)

**Problem:**
- Enabling the search bar and column sort on a table **lost settings on save/publish**.
- Table colors and fonts could not be controlled.
- The search bar was too wide on laptop; rows showed incorrect red/stripe color.

**Cause:**
- `table_search_*` and table style fields were not persisted in backend `dashboardJsonSchema.js`.
- A placeholder was incorrectly required to show search.
- `tableRowHoverBg` was applied on every alternate row (zebra stripe bug).

**Fix — Search & column sort:**
- Enable from the Search tab → settings persist after save/publish.
- Placeholder is **optional** — empty defaults to `"Search..."`.
- Position: left or right.
- Column sort: header click cycles asc → desc → off.

**Fix — Table styling (Property panel → Table tab → Table colors):**

| Setting | Field | Default |
|---------|-------|---------|
| Header text color | `tableHeaderColor` | `#64748b` |
| Header background | `tableHeaderBg` | `#f8fafc` |
| Body text color | `tableBodyColor` | `#475569` |
| Body background | `tableBodyBg` | `#ffffff` |
| Border color | `tableBorderColor` | `#e2e8f0` |
| Header font size | `tableHeaderFontSize` | 9 |
| Body font size | `tableBodyFontSize` | 10 |
| Row hover background | `tableRowHoverBg` | `#f8fafc` |

- Row hover: only on mouse hover; no odd/even stripes.
- Phone / nested: smaller font, reduced padding, horizontal scroll, sticky header.

**Search bar width:**
- Laptop top-level: `min(280px, 64vw)`
- Nested container: `min(240px, 60vw)`
- Phone / compact: full width

**Data flow (table settings save):**
1. Builder `PropertyPanel` → set `tableSearchEnabled`, `tableColumnSortEnabled`, `style.table*` on widget
2. `DashboardBuilder` → `chartConfigFromWidgetStyle` / `buildDashboardJsonPayload`
3. Backend `dashboardJsonSchema.js` → `table_search_*`, `table_header_*`, etc. in `chart_config`
4. Load / live → `WidgetRenderer` → `DashboardTableView` render

**Reflects:**
- Table widget → Search toggle, placeholder, position, column sort — saved on draft and publish
- Table colors panel controls heading, body, border, and font
- Table is readable on phone (scroll + compact)

**Files:**
- `frontend/src/features/dashboard-builder/components/PropertyPanel.js` — Search, sort, Table colors UI
- `frontend/src/features/dashboard-builder/components/WidgetRenderer.js` — `DashboardTableView`, `resolveTableVisualStyle`
- `frontend/src/features/dashboard-builder/components/DashboardBuilder.js` — defaults, merge style, chart config mapping
- `backend/src/apps/dashboard/utils/dashboardJsonSchema.js`
  - `readTableWidgetOptions`, `tableWidgetOptionsToChartConfig`
  - `tableStyleToChartConfig`, `readTableStyleFromChartConfig`
  - `widgetToStoredJson`, `widgetToRuntimeRow`
