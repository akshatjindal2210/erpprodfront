## A. Floating pixel dashboard builder

|           |                                      |
|-----------|--------------------------------------|
| **UI**    | Settings → Dashboard Builder           |
| **API**   | Save draft / publish (same routes)   |
| **DB**    | No schema change — `layout_px` in `mst_dashboard_configs.dashboard_json` |
| **Dates** | **14 Sep 2026**                      |

## What changed

The builder canvas is now **always floating pixels** (`USE_FLOATING_BUILDER = true`):

| Surface | Component |
|---------|-----------|
| Top-level laptop / phone canvas | `SimpleBuilderCanvas` |
| Nested widgets inside a container | `SimpleNestedCanvas` |

Positions persist as pixel boxes:

- Laptop: `layout_px`, per-widget `style.boxPx`, container `nestedLayoutPx`
- Phone: `layout_px_mobile`, `mobileNestedLayoutPx`

Phone and laptop layout stores are **isolated** — editing one mode does not rewrite the other.

## Why

Grid layout (`react-grid-layout`) could not match designer WYSIWYG. Separate pixel stores give true 1:1 preview on laptop and phone without cross-contamination.

## Builder UX (unchanged shortcuts)

| Action | Browser | PWA |
|--------|---------|-----|
| Save Draft | Ctrl+S | Ctrl+S |
| Publish | Ctrl+Alt+U | Ctrl+U |
| Undo / Redo | Ctrl+Z / Ctrl+Y | same |

## Live widget click links

Published dashboards support URL / APP / Drawer click navigation on floating canvas widgets — keyboard Enter/Space, `role="link"`, drawer via `resolveWidgetDrawerOpenPayload`.

## F. Column filter focus + click guards (drawers / overlays)

|           |                                      |
|-----------|--------------------------------------|
| **UI**    | App-wide — dashboard widget drawer + table column filters |
| **API**   | No change                            |
| **DB**    | No change                            |
| **Dates** | **14 Sep 2026**                      |

## Problem

1. Column filter menus portal to `document.body` — Tab order broke inside drawer overlays (v4.1.2 overlay focus guard did not cover dashboard builder popups).
2. Clicking column filter controls triggered widget URL/drawer navigation when the table widget had a click link configured.

## What changed

**Tab trap (`overlayFocusGuard.js`):**

- Portaled filter menu excluded from `inert` via `data-dashboard-column-filter-menu`
- Open filter builds focus chain: input → menu options
- Tab past last option closes menu and advances focus inside top overlay

**Click guard (`widgetClickLink.js` + canvas):**

- `shouldIgnoreWidgetLinkClick()` ignores `[data-dashboard-column-filter]`, `[data-dashboard-column-filter-menu]`, `table th`, `[data-no-widget-link]`
- `SimpleBuilderCanvas` drag `cancel` selector includes same markers

## Files

| File | Change |
|------|--------|
| `frontend/src/platform/utils/system/overlayFocusGuard.js` | Column-filter Tab chain |
| `frontend/.../dashboard-builder/components/DashboardTableColumnFilter.js` | Tab-exit event listener |
| `frontend/.../dashboard-builder/utils/widgetClickLink.js` | Ignore selectors |
| `frontend/.../dashboard-builder/components/SimpleBuilderCanvas.js` | Drag cancel selectors |

## I. Create Deviation — Schedule Qty display fix

|           |                                      |
|-----------|--------------------------------------|
| **UI**    | IMS → Packing Entry → Create Deviation drawer |
| **API**   | `POST /box/sticker/monthly-limit` (preview) |
| **DB**    | Read-only — `schedule_plan` + IMS API |
| **Dates** | **14 Sep 2026**                      |

## Problem

Schedule Qty showed **0** while Schedule Planning showed the correct total — drawer read only local `schedule_plan`; planning UI uses IMS schedule data.

## What changed

`sumItemScheduleQty()` in `monthlyPackingLimit.js`:

1. Sum from local `schedule_plan` (item + month, exclude reject/delete status 4, 5)
2. If zero → sum from IMS `fetchImsDataRaw("schdule")` for same item + month

Schedule Qty is **display only**. Allowed packing limit still uses approved shortage + tolerance % — not schedule.

Drawer fields: Schedule Qty · Shortage Qty · FG Stock · Used · Allowed · Excess.

## Files

| File | Change |
|------|--------|
| `backend/.../ims/lib/utils/inventory/monthlyPackingLimit.js` | `sumItemScheduleQty()` IMS fallback |
| `frontend/.../ims/modules/master/PackingDeviationDrawer.js` | Reads `limitInfo.schedule_qty` |

**Ops:** Restart backend. If IMS API is down, Schedule Qty may still show 0 when local DB is also empty.
