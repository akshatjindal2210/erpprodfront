### Issue Request — super admin MRN FIFO start

**Who:** `super_admin` only (frontend: `isRmstoreSuperAdmin(user, authRole)`; backend save: `isSuperAdminUser`).

**When:** Selected RM wire has **at least two distinct MRNs** in the issue pool (not “2 coils”). Pool = active coils, QC passed, store or coil area, minus coils reserved elsewhere.

**Where:** Issue Request modal → job card row → MRN table:

| Part | Super admin | Other users |
|------|-------------|-------------|
| Header (MRN UID column) | Label **MRN UID** + small dropdown | Label **MRN UID** only |
| Dropdown options | **Standard order** · **Start at N: #mrn_uid** | — |
| Table body | Reserved coils (after +/− pick) | Same |

Super admin sees the table (header + dropdown) as soon as the pool has 2+ MRNs, even before any coil is selected. Body rows appear after coils are picked.

**Behaviour:**

| Selection | Coil + / FIFO pick |
|-----------|-------------------|
| Standard order | Default MRN FIFO (mrn order → stored before unassigned → created_at → coil) |
| Start at 3 | MRN at FIFO position 3 first, then 4, 5, … then wrap to 1, 2 |

**Save API:** Super admin payload may include `fifo_start_mrn_uid` per job card. Backend uses it in `assertIssueRequestCoilsAvailable` only. **Not** saved on `issue_request_job_card`.

**Edit / reopen:** Start MRN is not loaded from DB; set again in the modal.

**Unchanged for non–super-admin:** SP1 mapped RM, first mapped RM, FIFO rules, and MRN table layout (no dropdown).

### Issue Request — Print Bill

Toolbar **Print** (and Ctrl+P) prints the full issue slip for the selected **Issue UID**. Works from **Issue Request** (master) and **Job Card Wise** — always the master document.

| Gate | Rule |
|------|------|
| UI | Button only when the selected row is **approved** |
| API | `POST /api/rmstore/issue-requests/print` — 409 until approved |
| Permission | `rm_issue_request` view |

**Header:** Company block, **S. No.** (Issue UID), **Date** (from approved or created). Shift and Created By / At are not printed.

**Line table** (one sub-row per reserved coil; job-card fields on the first coil row only):

| Column | Notes |
|--------|--------|
| S.No. | Job-card sequence |
| Job Card · Machine · FG Item · RM Item | RM Item column is wider |
| Count | Number of coils on that job card (`coils.length`, not string length) |
| MRN UID · Coil Qty | Per coil |
| Total Qty | Job-card issue qty (or sum of coil qty) on first row only |

**Footer:** **Req. Qty**; **Approved By** / **At**; optional remarks.

**Totals row:** Sum of **Coil Qty** and **Total Qty** across job cards.

Builder: `issueRequestPrintDocument.js`. Client: `printFromBackendHtml` (same as Forwarding Note / coil report).

### In-Process Request — Pending / Register

Same tab shell as QC Check / RM Rejection.

| Tab | Default | Data |
|-----|---------|------|
| **Pending** | Yes | Coils on shop floor (`status = out` **and** `out_uid` set) — live stock, no date window |
| **Register** | No | Saved IPR rows (`list`) — dates, type, approve status |

API: `POST /api/rmstore/in-process-requests/pending-shop-floor` (`shop_floor` filter on `findCoils`).

**Pending toolbar**

| Action | Behaviour |
|--------|-----------|
| **New** with a selected coil | Opens **Update Coil Status** directly (Full Consume / Left Over); scan / type pickers skipped |
| **New** with no selection | Normal New flow (Rejection vs Update Coil Status) |
| Double-click row | Same as New with that coil selected |
| View / Edit / Approve / Delete | Register only |

**Register** keeps the existing IPR list actions (View, Edit, Approve, Delete, Receive Store In when applicable).

### QC Check — require sticker scan (App Config)

Settings → Application Configuration → **RM Store** → **QC Check — require sticker scan**.

| Value | Behaviour |
|-------|-----------|
| **true** (default) | Pending **Check** opens scan gate (QC / coil sticker), then Spec form |
| **false** | Pending **Check** / double-click opens Spec form directly (no scan) |

Key: `qc_check_require_sticker_scan`. Draft rows still skip the scan gate. Coil and batch pending both supported when scan is off (same prepare / unlock path as a successful scan).

### MRN Portal — default No. of Coils from `it_lot_no`

Applies when opening **MRN Sticker** (`MrnStickerModal`) or **Reject before stickers** (`MrnRejectDrawer`) on a fresh MRN (no generated coils, no saved `sticker_draft`).

| Input | Default **No. of Coils** |
|-------|-------------------------|
| `it_lot_no` empty or contains non-digits (e.g. `17I264416495`) | `1` |
| Digits only after trim (e.g. `4`, `0004`) | Integer value, clamped **1–9999** (`0` → `1`) |
| Stickers generated / `coils[]` present | Actual coil count (regex not used) |
| `sticker_draft.coil_count` | Draft value (regex not used) |

Qty per coil follows existing rules (`qty_auto_calc` weighted split vs equal / manual lines). User can change coil count after the default.

**Convention:** ERP uses a purely numeric `it_lot_no` when it means coil count for that line. A long numeric lot that is not a coil count would be misread (adjust regex only if that appears in live data).

Detail API 404 fallback hydrates from the list row (`hydrateFromSourceRow` spreads row fields so `it_lot_no` is still available).

| File | Logic |
|------|--------|
| `MrnStickerModal.js` | `applyFreshInputs` |
| `MrnRejectDrawer.js` | `initialCoilCount` (reject only before sticker generation) |

### RM Inventory — Location Details column

Report SQL (`inventoryReport.model.js`) builds `location_details` for all coils in the group:

| Segment | Meaning |
|---------|---------|
| `{rack} (n)` | In store on a rack |
| `UA (n)` | Unassigned (if count > 0) |
| `SF (n)` | Shop floor (if count > 0) |
| `QC (n)` | Pending QC, informational (if count > 0) |

List UI (`inventory-report/Page.js`): hover tooltip on **Location Details** uses `total_stock_coil_uids` (full stock), not issuable-only UIDs.

### Store Out — permissions and list behaviour (IMS-aligned)

**Register tab:** Single click selects a row; double-click does not open the modal. Toolbar and modal actions check `rm_out_entry` add / edit / authorize / view; denied actions return silently (no extra permission toasts).

**Pending tab:** Double-click starts add (pending row), opens draft (edit), or view (scan complete) when permitted; missing permission → no modal, no toast. Incomplete scan → info toast to use **Draft**.

**Modal:** `CoilScanEntryModal` — `viewOnly` for read-only completed entries; `persist()` re-checks add / edit / authorize.

**DataTable:** Row-level `onDoubleClick` on `<tr>` so double-click works with `allowCopy` (`frontend/src/ui/primitives/DataTable.js`).

Related FE: `out-entry/Page.js`, `shared/CoilScanEntryModal.js`.
