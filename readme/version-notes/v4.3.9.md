### Issue Request — super admin MRN FIFO start

**Who:** `super_admin` only (frontend: `isRmstoreSuperAdmin(user, authRole)`; backend save: `isSuperAdminUser`).

**When:** Selected RM wire has **at least two distinct MRNs** in the issue pool (not “2 coils”). Pool = active coils, QC passed, store or coil area, minus coils reserved elsewhere.

**Where:** Issue Request modal → job card row → MRN table:

| Part | Super admin | Other users |
|------|-------------|-------------|
| Header (MRN UID column) | Label **MRN UID** + small dropdown | Label **MRN UID** only |
| Dropdown options | **Standard order** · **Start at N: #mrn_uid** | — |
| Table body | Reserved coils (after +/− pick) | Same |

Super admin sees the table (header + dropdown) as soon as the pool has 2+ MRNs, even before any coil is selected. Body rows appear after coils are picked.

**Behaviour:**

| Selection | Coil + / FIFO pick |
|-----------|-------------------|
| Standard order | Default MRN FIFO (mrn order → stored before unassigned → created_at → coil) |
| Start at 3 | MRN at FIFO position 3 first, then 4, 5, … then wrap to 1, 2 |

**Save API:** Super admin payload may include `fifo_start_mrn_uid` per job card. Backend uses it in `assertIssueRequestCoilsAvailable` only. **Not** saved on `issue_request_job_card`.

**Edit / reopen:** Start MRN is not loaded from DB; set again in the modal.

**Unchanged for non–super-admin:** SP1 mapped RM, first mapped RM, FIFO rules, and MRN table layout (no dropdown).

### Issue Request — Print Bill

Toolbar **Print** (and Ctrl+P) prints the full issue slip for the selected **Issue UID**. Works from **Issue Request** (master) and **Job Card Wise** — always the master document.

| Gate | Rule |
|------|------|
| UI | Button only when the selected row is **approved** |
| API | `POST /api/rmstore/issue-requests/print` — 409 until approved |
| Permission | `rm_issue_request` view |

Document fields: Issue UID, Shift, Date, FG / RM, Part Wt / RM Wt; line table Job Card · Machine · Issue Qty · Coil No · **Heat No** · **MRN No** · Coil Qty; Created / Approved footer and remarks.

Builder: `issueRequestPrintDocument.js`. Client: `printFromBackendHtml` (same as Forwarding Note / coil report).

### In-Process Request — Pending / Register

Same tab shell as QC Check / RM Rejection.

| Tab | Default | Data |
|-----|---------|------|
| **Pending** | Yes | Coils on shop floor (`status = out` **and** `out_uid` set) — live stock, no date window |
| **Register** | No | Saved IPR rows (`list`) — dates, type, approve status |

API: `POST /api/rmstore/in-process-requests/pending-shop-floor` (`shop_floor` filter on `findCoils`).

**Pending toolbar**

| Action | Behaviour |
|--------|-----------|
| **New** with a selected coil | Opens **Update Coil Status** directly (Full Consume / Left Over); scan / type pickers skipped |
| **New** with no selection | Normal New flow (Rejection vs Update Coil Status) |
| Double-click row | Same as New with that coil selected |
| View / Edit / Approve / Delete | Register only |

**Register** keeps the existing IPR list actions (View, Edit, Approve, Delete, Receive Store In when applicable).

### Store In — pending in-process (machine)

**Unassigned / PENDING RECEIVE** queue only:

- List: Machine column when IPR enrich provides `macname`.
- Receive modal: Machine info field.

Source: `enrichIprMachineLabels` on in-process **pending Store In** API (`getPendingStoreIn`). **Not** written to inventory inward register rows.

Main UI: `inventory-inward/Page.js`, `ReceivePendingStoreInModal.js`.
