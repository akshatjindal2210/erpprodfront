## v3.4.35 — Forwarding Note & Stock Adjustment

UI and filter refinements for **IMS → Forwarding Note** and **IMS → Stock Adjustment**. 

|   |   |
|---|---|
| **UI** | `/ims/` → Forwarding Note · Stock Adjustment |
| **Scope** | Frontend behaviour (list filters, New flow, SA gate defaults, print stickers) |

---

### 1. Forwarding Note — Master **New** without direct-create permission

**Problem:**
- Users without the IMS special permission **Direct Forwarding Note** saw a toast asking them to switch to **Today Dispatch Plan** and click **New**.
- That forced an unnecessary tab change for the same schedule-based create flow.

**Fix:**
- On **Forwarding Master → New**, if `direct_forwarding_note` is **not** granted, open the **same** create path as Today Dispatch Plan → New (blank schedule-catalog modal, or prefill when a dispatch row is selected).
- `customerSchedulePicker` is enabled for that path even while the outer tab remains Forwarding Master.
- Users **with** Direct Forwarding Note keep blank direct create on Master (unchanged).

**Flow:**

| User | Forwarding Master → New | Today Dispatch Plan → New |
|------|-------------------------|---------------------------|
| Module Add only | Schedule-catalog create (no tab switch) | Schedule-catalog create |
| Add + Direct Forwarding Note | Direct blank create | Schedule-catalog create |

**Files:**
- `frontend/src/apps/ims/modules/forwarding-note/ForwardingPage.js`

### 2. Forwarding Note — Hub bill Quick Search, bill colour, list filters

**Problem:**
- Hub / external bill numbers (`billno` from IMS `invfnote` enrich) were not included in Quick Search.
- External bill colour lived in a separate **Status** column (e.g. GREEN) while Bill No. / Bill Date stayed neutral.
- Changing date or dropdown filters could apply immediately; operators expected date range to wait for **Search**, and Status / Lock to filter the loaded grid instantly.

**Fix:**

| Area | Behaviour |
|------|-----------|
| **Quick Search** | Client-side search includes hub `billno`, `billdt`, and external `status`, plus existing fields (`bill_no`, customer, FUID, etc.). Search is not sent to the list API so enrich-only hub bills remain findable. |
| **Bill display** | External status colour is applied to **Bill No.** and **Bill Date** text. The standalone external Status (colour-name) column is removed. Authorized / Pending and Lock Status columns are unchanged. |
| **Date range** | From / To apply only when the user clicks **Search** (or uses the filter Apply path). No auto-apply on date pick. |
| **Status** | Authorized / Pending — **frontend** filter on already-loaded rows; applies on change. |
| **Lock / Complete** | Locked / Unlocked / Complete — **frontend** filter on already-loaded rows; applies on change. |

**Notes:**
- Date-scoped data still comes from the API (`from_date` / `to_date`). Status and Lock only narrow that loaded set.
- Card view `badgeIndices` adjusted after the external Status column removal.

**Files:**
- `frontend/src/apps/ims/modules/forwarding-note/ForwardingPage.js`

### 3. Stock Adjustment — Update **Action** defaults to Minus (−)

**Problem:**
- On entry type **Update**, Action defaulted to **Add (+)**. Operators more often need **Minus (−)** first.

**Fix:**
- Default Action is **Minus (−)** for new Update flows (initial state, reset, type change, box scan, packing load).
- Button order shows Minus before Add.
- Hydration of an existing Update still uses the saved `update_action`; if missing, fallback is Minus.

**Files:**
- `frontend/src/apps/ims/modules/stock-adjustment/StockAdjustmentStickerCloneDrawer.js`
- `frontend/src/apps/ims/modules/stock-adjustment/hydrateStockAdjustmentStickerView.js`

---

### 4. Stock Adjustment — Print Stickers: category / customer read-only

**Problem:**
- On **Print Stickers**, Packing Category rendered as an editable **Select category** control while Item Details and Customer were presentation-only, which was confusing on a print-only screen.

**Fix:**
- Print Stickers passes `categorySelectDisabled` and `customerSelectDisabled` so category and customer match the read-only detail pattern.
- Category label is resolved from packing / adjustment detail when available.

**Files:**
- `frontend/src/apps/ims/modules/stock-adjustment/StockAdjustmentPrintStickersDrawer.js`

---

### 5. Stock Adjustment — Add (+): auto-select current financial year

**Problem:**
- Choosing Type **Add (+)** left Financial Year on **Select…**, requiring a manual pick every time (RM Store already defaulted FY).

**Fix:**
- Selecting **Add (+)** sets Financial Year to the current Indian FY (`YYYY-YYYY+1`), same helper pattern as RM Store.
- Switching away from Add clears FY. User can still change FY in the dropdown before Load.

**Files:**
- `frontend/src/apps/ims/modules/stock-adjustment/StockAdjustmentStickerCloneDrawer.js`
