## Today Dispatch Plan — Recommended by Customer (sort, boxes, Sch No)

Date: **2 Sep 2026**  
Scope: **IMS → Forwarding Note → Today Dispatch Plan**

---

### 1. Recommended by Customer — top row = highest dispatch qty

**Problem:**
- Customer rows used the same **Match %** sort as item-wise (worst item % on the customer row).
- Operators want to see first the customer they can **dispatch the most qty** to (e.g. 2 items × 2000 before 10 items × 1000).

**Solution:**

| View | Top row rule | Where |
|------|----------------|--------|
| **Recommended by Item** | Match % (100% first) → workable qty → action date → sch no | Unchanged — backend + frontend `compareRecommendedDispatchRows` |
| **Recommended by Customer** | **Total Rec. Dispatch Qty** (sum of item workable qty) highest first; tie → item-wise rules | Frontend only — `compareRecommendedCustomerRows` |

Customer grouping stays on the frontend (`groupRecommendedByCustomer`). Same API as item-wise (`status: recommended`).

**Files:**
- `frontend/src/apps/ims/modules/forwarding-note/TodayDispatchPlanTab.js`

---

### 2. Total Boxes — simple count (no full / loose)

**Problem:**
- Backend sent `dispatch_full_boxes` + `dispatch_loose_boxes`; when packing standard was missing, both were `0` and UI showed **Total Boxes = 0** even with dispatch qty (e.g. 490).
- Full/loose split was more complex than needed for this column.

**Solution:**

| Layer | Behaviour |
|-------|-----------|
| **Backend** | One field: `dispatch_box_count` = boxes from workable qty ÷ `qty_per_box` (remainder → +1). No standard but qty > 0 → **1**. |
| **Frontend** | Shows `dispatch_box_count` (customer row = sum of item counts). |

**Files:**
- `backend/src/apps/ims/modules/schedule-planning/utils/service/schedulePlanService.js`
- `frontend/src/apps/ims/modules/forwarding-note/TodayDispatchPlanTab.js`

---

### 3. Recommended by Customer — hide Sch No on outer row

**Problem:**
- Outer customer row showed comma-separated Sch Nos; operators only need Sch No on the **expanded item lines**.

**Solution:**
- Outer customer table: no **Sch No** column (Customer, Item (Dispatch Qty), Rec. Dispatch Qty, Total Boxes, Status).
- Double-click expand / item sub-table: **Sch No** still shown (item-wise columns).

**Files:**
- `frontend/src/apps/ims/modules/forwarding-note/TodayDispatchPlanTab.js`
