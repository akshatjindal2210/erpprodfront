## 1. Canonical IPR types

### Why

After dropping legacy columns (`request_type`, `rejection_type`, `downstream`, …), list Type often defaulted wrong (everything looked like Rejection or Consume). Operators need the Type column to match what they picked on **Update Coil Status** and rejection scope.

### Canonical values (DB `type`)

| `type` | Meaning | Typical UI |
|--------|---------|------------|
| `consume` | Full consume, or leftover consume (balance → Store In) | **Consume** / **Return** badge |
| `return` | Pure Store In request | **Store In** |
| `reassign` | Partial consume; balance stays on shop floor on another JC | **Reassign** |
| `reject_coil` | In-process rejection — coil scope | **Reject Coil** |
| `reject_lot` | In-process rejection — lot scope | **Reject Lot** |

### Legacy mapping (API still exposes)

| Canonical `type` | Alias `request_type` | Alias `downstream` / `stage` |
|------------------|----------------------|------------------------------|
| `return` | `store_in` | `pending_store_in` / `store_in_done` |
| `consume` / `reassign` | `consume` | `consumed` or `pending_store_in` (leftover) |
| `reject_coil` / `reject_lot` | `rejection` | `pending_store_out` / `store_out_done` |

`rejection_type` alias remains `coil` / `lot` for modal scope (separate from DB `type`).

### Boot migration

On table ensure:

1. Rename `type = 'coil'` → `reject_coil`, `type = 'lot'` → `reject_lot`.
2. Light recovery for empty / wrong `coil`-era rows from `stage` / reason (leftover Update Status stays `consume`).
3. Rows with `reassign_jc` or coil `reassign: true` forced to `reassign`.
4. **Do not** copy coil `pjobcardno` into `reassign_jc` (source ≠ target).

Heavy legacy backfill stays behind `RUN_IPR_BACKFILL` (default `false`).

**After deploy — turn backfill off:** keep `RUN_IPR_BACKFILL = false`. When types look correct, comment out `await recoverIprTypeLight()` in `createRmStoreInProcessRequestTable`. Never re-enable `backfillReassignJcLight`. Full steps: [in-process-request.md](../module-flow/rmstore/in-process-request.md) → **Boot backfill**.

## 5. Update Coil Status — Return qty → Store In

### Problem

Operators selected **Return** and typed the full coil qty (e.g. 36) expecting Store In receive. The field was treated as **consumed qty**, so `remaining = 0` saved as **Full Consume** and nothing queued for Store In.

### Fix

| Mode | Field meaning | Save |
|------|---------------|------|
| **Full Consume** | Entire coil used at machine | `consumed = total`, `remaining = 0` |
| **Return** | **Return qty** = amount to Store In | `remaining = return qty`, `consumed = total − return` |
| **Reassign** | Consumed on current JC | Balance stays on shop floor on target JC |

- Return requires return qty **> 0** and **≤ total**.
- Placeholder shows total qty; typing capped at max.
- Approve path unchanged: leftover with `remaining > 0` → `pending_store_in`.

### Files

| Area | Files |
|------|--------|
| FE form | `UpdateCoilStatusForm.js` |
| FE handlers / validate | `InProcessRequestModal.js` |

## 6. Coil reassign JC chain (list + Finder)

### Problem

After multiple reassigns (e.g. JC-A → JC-B → JC-C), Coils table and Coil Finder showed only the latest JC. Intermediate job cards were missing.

### Root cause

IPR coils are **slimmed on write** (`slimCoilForStorage`): split lines store `original_qty` + `remaining_qty`, **not** `consumed_qty`. Enrichment that required `consumed_qty > 0` skipped every source hop and kept only the final balance JC.

### Fix

1. **`deriveIprLineQtys`** — same as `normalizeCoils`: when consumed is missing/0, `consumed = original − remaining`.
2. **`loadReassignHistoryByCoilUids`** — batch-load approved IPR rows (`type = reassign` or `reassign_jc` set) whose coils JSON contains the coil UID; build ordered hops (source = line `pjobcardno`, target = `reassign_jc`).
3. **Machines** — `findMacnamesForJobCards` on IR job-card master (JC prefix normalized).
4. **`enrichCoilsWithReassignHistory`** — after coil list/detail fetch, attach `reassign_history` then `enrichCoilJobCardDisplay` → `job_card_assignments` + `pjobcardno_label` like `JC-A (qty), JC-B (qty), JC-C (qty)`.
5. Wired into `findCoils`, `findCoilByUid`, `fetchCoilsWithMrnDetails`.

SQL `COIL_REASSIGN_JOIN` may still expose latest scalars / history jsonb; **JS batch enrich is the source of truth** for the full chain (slim coils).

### Coil Finder UI

| Card | Content |
|------|---------|
| **This coil** | Latest JC `(qty)` + Machine (same layout as before) |
| **History** | Earlier JCs; list order **desc** (recent previous first); labels count **N … 1** (oldest = **1** at bottom) |
| Style | Same shell/header tone as Current area; compact 2-col Job card \| Machine |

### Removed

| Item | Why |
|------|-----|
| `repairReassignCorruptedOutJobCards` | One-off heal that rewrote `out_entry.pjobcardno` on every Pending Shop Floor load — not wanted; JC/Machine come from IR + IPR joins |

### Example

Reassign hops: JC-14123 → JC-13574 → JC-13972 (balance 50)

| Surface | Display |
|---------|---------|
| Coils table JOB CARD | `JC-14123 (…), JC-13574 (…), JC-13972 (50)` |
| Finder This coil | `JC-13972 (50)` + machine |
| Finder History | **2** · JC-13574 … then **1** · JC-14123 … |

## 7. Inventory Report — no change

RM Inventory Report does **not** join `rmstore_in_process_request` and does **not** read IPR `type`.

| Bucket | Source |
|--------|--------|
| In Store / Unassigned / Shop Floor | Coil location + `out_uid` + status |
| Issuable | Warehouse + QC passed + not rejected |
| RM Rejection (`pending_reject_qty`) | Coil `status = rejected` and/or QC failed |

Approving an IPR rejection still sets coil `status = 'rejected'` (unchanged). Renaming IPR types to `reject_coil` / `reject_lot` does not alter report math.

## 9. RM Rejection — live bill match, Complete, supplier, bill lock

### Flow

| Step | Behaviour |
|------|-----------|
| MRN / QC / IPR reject | Row in **Pending** (Awaiting Bill) and **Register** (Incomplete until bill) |
| Auto-match | IMS **`invfnote`**, only **`salecat = 2`**, match **acc + item + qty** → show bill on list **without save** |
| Complete | Pending → pick bill + remark → save `bill_no` / `bill_dt` → Register **Complete** |
| Dropdown | Super Admin = all salecat-2 bills; normal user = same vendor/item only |
