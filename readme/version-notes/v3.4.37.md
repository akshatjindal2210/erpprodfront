## Shortage, Schedule Planning & Today Dispatch Plan — Filters & Recommended Sort

Date: **1 Sep 2026**  
Scope: **IMS → Shortage**, **IMS → Schedule Planning**, **IMS → Forwarding Note → Today Dispatch Plan**

---

### 1. Shortage — Default month filter & Custom date range

**Problem:**
- Shortage list showed all months with no date control.
- Operators needed the same pattern as Schedule: **Default** = current work scope, **Custom** = month or date range when viewing older data.

**Solution:**

| Report | Behaviour |
|--------|-----------|
| **Default** | Table loads **current month only** (`month` column). From/To date fields are **disabled**. |
| **Custom** | Month dropdown + From/To date enabled. At least one of Month or Date is required before Search. |
| **Reset** | Clears filters and returns to Default (current month). |

Switching Report back to **Default** reloads current-month data immediately (no extra Search click).

**Files:**
- `frontend/src/apps/ims/modules/shortage/Page.js`

### 2. Schedule Planning — Default IMS API (no filter)

**Problem:**
- On **Report = Default**, extra DB-only rows (not in IMS response) were merged into the list, so the grid did not match pure IMS data.
- Requirement: Default must call IMS with **only** `{ "requestedData": "schdule" }` — no `filter: "m.fyid = …"` or month SQL.

**Solution:**

| Report | IMS request | List data |
|--------|-------------|-----------|
| **Default** | `{ "requestedData": "schdule" }` only | IMS rows + plan status merge; **no** orphan DB-only rows |
| **Custom** | `{ "requestedData": "schdule", "filter": "m.fyid = … and …" }` | Filtered IMS + scoped DB orphans |

`fin_year_id` from the UI still goes to **our backend** for plan/Hold/Ready merge — it is **not** sent to IMS on Default.

Schedule page initial load no longer waits on date-filter defaults (not needed for Default view).

**Files:**
- `backend/src/apps/ims/modules/schedule-planning/utils/service/schedulePlanService.js`
- `frontend/src/apps/ims/modules/schedule-planning/Page.js`

### 3. Today Dispatch Plan — Recommended tab (Forwarding Note)

**Problem:**
- **Recommended** used DB-only load and did not align with IMS + stock-based dispatch priority.
- Operators need rows where **balance > 0** and **FG stock > 0**, sorted so **full stock coverage (100% match) is on top**, lower match % below.

**Solution:**

**Plan** and **Complete** tabs — **unchanged**.

**Recommended** tab:

| Rule | Detail |
|------|--------|
| Data source | IMS default API + plan DB merge (current `schmonth`) |
| Status | Plan, Running, or Ready to Dispatch only |
| Include | `balance_qty > 0` **and** `fg_stock_qty > 0` |
| Exclude | Hold, Reject, Complete, other months |
| Sort (top → bottom) | 1. Match % (100% first) → 2. Workable qty → 3. Action date → 4. Sch no |

**Match %** = `min(FG stock, balance) ÷ balance × 100`  
Row colours: green = stock covers full balance; amber = partial.

- `backend/src/apps/ims/modules/schedule-planning/utils/status/schedulePlanStatus.js`
- `frontend/src/apps/ims/modules/schedule-planning/schedulePlanStatus.js`
- `frontend/src/apps/ims/modules/forwarding-note/TodayDispatchPlanTab.js`
