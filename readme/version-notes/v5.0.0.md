## v5.0.0 · Part B — Document IDs · Upload fixes · Prime Item Master · Row double-click details

With this release, each module record also stores the IDs of its documents, so the link now works in both directions. `documents.mod_ref` now stores the real record ID as text instead of a numeric hash. ## 4. Document IDs on module records

> **Replaced in Part C.** The module record now stores `<uuid>.<ext>` file names (`tc_file`, `rmtc_file`, `doc_files`), and `updateDocIds` is no longer called. The ID columns below are kept but no longer written. See section 14.

### How it works

```
upload → file saved in documents → await updateDocIds(MODULE, recordId) → document ID(s) saved on the record
```

`updateDocIds` reads the record's **active** documents (`status = true`) and writes their IDs to the record. One call covers save, replace and remove:

| Action | Single upload (`tc_doc_id` / `rmtc_doc_id`) | Multiple uploads (`doc_ids`) |
|--------|---------------------------------------------|------------------------------|
| Save | New ID is set | New ID is added to the array |
| Replace | Overwritten with the new ID | Old ID removed, new ID added |
| Remove | Set to `NULL` | ID removed from the array |

- Replaced or removed documents stay in `documents` with `status = false` (history is kept).
- TC and RMTC are identified by their upload folder (`/tc/`, `/rmtc/`).
- If the ID update fails, the upload still succeeds and a warning is logged.

### Module → table → column

| Module (`mod_type`) | Table | Key | Column(s) |
|---------------------|-------|-----|-----------|
| `rm_mrn_portal` | `rmstore_mrn` | `uid` | `tc_doc_id`, `rmtc_doc_id` |
| `rm_stock_adjustment` | `rmstore_stock_adjustment` | `adjustment_id` | `tc_doc_id`, `rmtc_doc_id` |
| `rm_qc_check` | `rmstore_qc_check` | `qc_check_uid` | `doc_ids` |
| `rm_in_process_request` | `rmstore_in_process_request` | `ipr_uid` | `doc_ids` |
| `invoice_receiving` | `ims_gate_entry` | `uid` | `doc_ids` |
| `eng_machine_master` | `eng_machine_master` | `id` | `doc_ids` |
| `tasks` | `task_chat` | `chat_id` | `doc_ids` |

### Where `updateDocIds` is called

| Controller | Called after |
|------------|--------------|
| Invoice Receiving — update / delete | `syncDocumentPaths` / `removeAllActive` |
| MRN TC/RMTC — `mergeMrnDocUploads` | TC/RMTC upload (when files were sent) |
| Stock Adjustment — `uploadSaDocs` | TC/RMTC upload (when files were sent) |
| QC Check — `persistQcItemsWithDocuments` | `replaceQcCheckItems` |
| In-Process Request — `saveIprAttachmentsToDocuments` | `syncPathsFromList` |
| Machine Master — create / update | `syncAttachmentList` |
| Task Chat — `sendMessage` | `saveFiles` |

Task chat delete does not update IDs because the chat row itself is deleted.

### Migration

> Removed in Part C (columns no longer used).

`backend/src/migrations/v5.0.0/docIdColumns.js` runs automatically on boot (`runVersionMigrations`). It only adds the new nullable columns (`ADD COLUMN IF NOT EXISTS`, no default) and skips tables that do not exist. Safe to run more than once.

## 5. `documents.mod_ref` stores the real ID

| Before | After |
|--------|-------|
| `mod_ref BIGINT` | `mod_ref VARCHAR(100)` |
| `toModRef("4130_1")` → `3319513234357271` (MD5 hash, not reversible) | `toModRef("4130_1")` → `4130_1` |
| `toModRef(531)` → `531` | `toModRef(531)` → `531` |

- `toModRef()` now only trims the value. All callers (save, list, history, backfill, `updateDocIds`) use it, so no other change was needed.
- `getActiveDocumentsMany` now uses `ANY($2::text[])` instead of `bigint[]`.

## 6. MRN Portal — remark carried over to the next entry

**Problem.** When the MRN modal was opened for a different entry, the TC/RMTC files were cleared but the remarks were not. The previous remark appeared on the new entry and was saved with its upload.

**Fix.** Wherever the modal clears the TC/RMTC files (fresh load, draft load, after save), it now also clears `tcRemark` and `rmtcRemark`.

---

## 7. Invoice Receiving — attachment remarks cleared on edit

There are two separate remarks, and they are never mixed:

| Remark | Stored in | Request field |
|--------|-----------|---------------|
| **Record remark** | Module table (`remarks`) | `remarks` |
| **Attachment remark** (one per file) | `documents.remark` | `file_remarks` / `doc_remarks` / `tc_remark` / `rmtc_remark` |

**Problem.** On edit or approve, the frontend sends remarks only for newly added files. The backend treated the missing remarks of existing files as empty and cleared them.

**Fix.** In `moduleDocuments.js`, an existing file with no remark sent keeps its saved remark. A remark is only changed when one is actually sent. In-Process Request (which sends remarks for every file) is not affected.

## 8. Machine Master — attachments

### UI

- Same attachment layout as Invoice Receiving: file icon, name, remove button, and the per-file remark shown below.
- Clicking a file opens the shared in-app preview (`FilePreviewLink`) instead of a new browser tab. Images and PDFs are previewed; other types are downloaded.
- New files show a "Remark (optional)" field.

### File validation

| Check | When | Message shown to the user |
|-------|------|---------------------------|
| File type not allowed | On file pick (file is skipped) | "Not allowed: *file*. Use PDF, image, Word, Excel, CSV or TXT." |
| File larger than 20 MB | On file pick (file is skipped) | "File too large: *file* (*size* MB). Max 20 MB per file." |
| Wrong type reaches the server | On save (HTTP 400) | "Invalid file type: *file*. Allowed: PDF, image, Word, Excel, CSV, TXT." |
| Large file reaches the server | On save (HTTP 400) | "File is too large. Each file must be 20 MB or less — please choose a smaller file." |

Allowed types: PDF, PNG, JPG/JPEG, WEBP, GIF, DOC/DOCX, XLS/XLSX, TXT, CSV. The backend filter now checks the file extension (previously the MIME type, which rejected Excel files).

The global error handler returns these upload errors as HTTP 400 with the real message instead of a generic 500. This also applies to the other upload screens (e.g. "Only PDF or image files allowed" in RM Store).

## 12. Prime Item Master — New form (processes, machines, wires)

Clicking **New** on Prime Item Master opens a dedicated form. **Edit** and **Approve** still open the existing Item RM Master form. This step is **UI only**: the **Add** button validates the form and logs the payload to the browser console. Nothing is saved yet.

### Form flow

```
Production Item ▼
Process ▼  [+ Add Process]

┌ Process #1  <process name> ───────────────────────────── 🗑 ┐
│ Machine 1 ▼ (machines of this process)   Wire (RM) ▼      🗑 │
│ Machine 2 ▼                              Wire (RM) ▼      🗑 │
│                                           [+ Add Machine]    │
└──────────────────────────────────────────────────────────────┘
```

| Step | Behaviour |
|------|-----------|
| Production item | Picked from ERP (same picker as Item RM Master) |
| Process | Approved processes from Process Master; **Add Process** adds a card (IMS Forwarding Note row style). The same process cannot be added twice. |
| Machines | Each process card has one or more machine rows; **Add Machine** adds a row. The picker lists only approved machines of that process. |
| Wire (RM) | Per machine. Lists the RM wires already mapped to the selected production item in RM Store → Item RM Master (`rmstore_master_production.rm_items`). If none are mapped, a notice is shown and the dropdown is disabled. Changing the production item clears the wire picks. |
| Add | Requires a production item, at least one process, a machine and a wire in every row, and no duplicate machine within a process. Then logs the payload. |

### Payload (console)

```js
[Prime Item Master] add payload: {
  item_dcode: 12451,
  processes: [
    { process_id: 3, machines: [{ machine_id: 1, wire_dcode: "2265" }, { machine_id: 2, wire_dcode: "2270" }] }
  ]
}
```

## v5.0.0 · Part C — UUID file names for documents · Process stage rule removed

### 12 Oct 2026

**Summary.** Every uploaded file now gets a **UUIDv7** and is saved as `<uuid>.<ext>` in the same module folder as before. The module record stores this file name (not the document ID), so a file can be shown with **module folder + stored name** and no join. The `documents` table keeps the path and metadata (type, size, remark, uploader) and is looked up by `uuid` only when needed. Engineering Process Master no longer limits START / END to one process each. All upload code now lives in one common module, `lib/documents/`.

No upload folders were moved and API response shapes are the same; paths in responses now end in `<uuid>.<ext>`. The `documents` table now uses `uuid` (`<uuid>.<ext>`) as its primary key, and the backfill removes the old path columns once their files are moved (see section 15, step G).

| Area | Change |
|------|--------|
| **File name** | All multer uploads save as `<uuidv7>.<lowercase ext>` |
| **`documents.uuid`** | **Primary key** = `<uuid>.<ext>` (no numeric `id`). QC `document_id` and replace / remove use it |
| **Module record** | `tc_file` / `rmtc_file` (single upload) or `doc_files` JSONB array (multiple uploads) |
| **Old path / ID columns** | No longer written. Old file paths are moved by the backfill, then `tc_file_path` / `rmtc_file_path` / `tc_file_name` (MRN, SA) and `task_chat.attachments` are dropped |
| **Reading** | Folder + stored name. Metadata comes from `documents` by `uuid` |
| **Backfill** | Old files are copied to `<uuid>.<ext>` (old file kept) and module columns are filled |
| **Process Master** | Any number of processes may use START or END |

## 14. UUID file names

### What / why / outcome

| | |
|--|--|
| **What** | One UUIDv7 per uploaded file. The same value is the file name and `documents.uuid`. |
| **Why** | Show or download a file straight from the module record, without joining `documents`. UUIDv7 is time-ordered, which suits PostgreSQL indexes. |
| **Outcome** | `<module folder>/<uuid>.<ext>` is the file. The module record holds `<uuid>.<ext>`. `documents` holds the metadata. |

### Flow

```
multer saves <uuid>.<ext>
  → documents service, one transaction:
       insert documents row (uuid, doc_path, doc_type = ext, size KB, remark)
       add <uuid>.<ext> to the module record column
```

### `documents` table (light)

| Column | Why it is needed |
|--------|------------------|
| `uuid` | **Primary key** — `<uuid>.<ext>`; also stored on the module record / QC `document_id` |
| `doc_path` | Module **folder only** (e.g. `uploads/rmstore/qc/`); full public path = folder + `uuid` |
| `doc_type` | Extension (`pdf`, `png` …) |
| `doc_size` | Size in KB |
| `remark` | Per-file note |
| `mod_type`, `mod_ref` | Which module record the file belongs to |
| `created_by`, `created_by_name`, `created_at` | Uploader and time. Rows moved by the backfill: `created_by = NULL`, `created_by_name = system` |
| `status` | `false` = replaced / removed (row is kept as history) |

`doc_name` (original upload name) was removed — screens show the file name from the path (`<uuid>.<ext>`). Older databases keep the column (made nullable) but new rows don't write it.

| Action | Single (`tc_file` / `rmtc_file`) | Multiple (`doc_files`) |
|--------|----------------------------------|------------------------|
| Upload | Set to the new name | New name added to the array |
| Replace | Old row `status = false`, new row with a new uuid, name swapped | Old name removed, new name added |
| Remove | Row `status = false`, column set to `NULL` | Name removed from the array |

- The documents row and the physical file are never deleted.
- The module record is updated directly: upload adds the name, replace swaps it, remove takes it out. TC or RMTC is picked from the upload folder (`/tc/`, `/rmtc/`).
- `updateDocIds` calls were removed from the controllers. The service now updates the module record inside its own transaction.
- If a file reaches the service from another folder, or without a uuid name, it is copied to `<module folder>/<new uuid>.<ext>`.
- QC Check: if the same file is sent back on edit, only the remark is updated. No new row or copy is made.

### Module → table → column → folder

| Module (`mod_type`) | Table | Key | Column(s) | Folder |
|---------------------|-------|-----|-----------|--------|
| `rm_mrn_portal` | `rmstore_mrn` | `uid` | `tc_file`, `rmtc_file` | `uploads/rmstore/tc`, `uploads/rmstore/rmtc` |
| `rm_stock_adjustment` | `rmstore_stock_adjustment` | `adjustment_id` | `tc_file`, `rmtc_file` | `uploads/rmstore/tc`, `uploads/rmstore/rmtc` |
| `rm_qc_check` | `rmstore_qc_check` | `qc_check_uid` | `doc_files` | `uploads/rmstore/qc` |
| `rm_in_process_request` | `rmstore_in_process_request` | `ipr_uid` | `doc_files` | `uploads/rmstore/ipr` |
| `invoice_receiving` | `ims_gate_entry` | `uid` | `doc_files` | `uploads/ims/invoice-receiving` |
| `eng_machine_master` | `eng_machine_master` | `id` | `doc_files` | `uploads/eng/machine` |
| `tasks` | `task_chat` | `chat_id` | `doc_files` | `uploads/task_tasks/chat` |

Single source: `DOC_FILE_LINKS` in `backend/src/lib/documents/documents.config.js`. Each entry also holds the allowed file types (`exts`).

### One upload middleware for all document modules

```js
router.post("/create", ..., docUpload(MODULE).array("attachments", 20), create);
router.post("/upload-docs", ..., docUpload(MODULE).fields([{ name: "tc" }, { name: "rmtc" }]), upload);
```

`docUpload(MODULE)` (`backend/src/lib/documents/documents.upload.js`) reads the module entry in `DOC_FILE_LINKS`:

| From the registry | Used for |
|-------------------|----------|
| `folder` / `slots[field].folder` | Upload folder (TC / RMTC picked by the field name) |
| `exts` | File type check by extension. Error: `Invalid file type: <name>. Allowed: …` |
| `maxMb` (optional) | Max size per file, default `DEFAULT_MAX_MB` = 20. The size error shows this module's limit. |
| — | File name `<uuidv7>.<lowercase ext>` |

It replaced 5 separate multer setups (`rmTcUpload`, `rmQcDocUpload`, `rmIprUpload`, `invoiceReceivingUpload`, `engineeringMachineUpload`) and the task chat upload.

### Future changes — where to edit

| Need | Backend | Frontend |
|------|---------|----------|
| **New file type** for a module | Add it to that entry's `exts` in `DOC_FILE_LINKS` (or to a shared `EXT` list) | Same extension in `frontend/src/lib/documents/index.js` (`CFG`); `uploadAccept(moduleKey)` on the input |
| **Bigger files** for a module | Set `maxMb` on that entry | Optional UI hint only — enforcement is backend |
| **Bigger files for all** | Change `DEFAULT_MAX_MB` | Same as above |
| **New document module** | 1. Entry in `DOC_FILE_LINKS` (`table`, `key`, `multi` + `folder` or `slots`, `exts`). 2. `docUpload(MODULE)` on the route. 3. Save with `moduleDocuments(MODULE)`. Restart → column is created by `createDocumentsTable()`. | Add matching `CFG` key; preview with `uploadUrl(path)`; see `frontend/src/lib/documents/README.md` |

No other file needs changing. Caddy has no request body limit, and multipart uploads are not limited by `express.json`.

| Behaviour change | Detail |
|------------------|--------|
| Invoice Receiving | `.doc` / `.docx` keep their real extension (before: saved as `.bin`). File check is by extension, not mimetype. |
| Task chat | File check is by extension (PDF, image, Word). Files always go to `uploads/task_tasks/chat`. |
| RM Store | Error text is now `Invalid file type: … Allowed: PDF, PNG, JPG, JPEG, WEBP.` |

Non-document uploads (task create / self-note / recurring / CL task, CSV import) keep their own multer, with uuid file names.

### Reading

- **Show / download:** `fileDocPath(folder, name)` → `uploads/<module folder>/<uuid>.<ext>`.
- **Metadata** (remark, size, uploader): `listActive(ref, { metadata: true })` / `listActiveMany(refs, { metadata: true })` — one `WHERE uuid = ANY(...)` query for the whole list. Without `metadata` only paths are returned.
- Screen helpers load metadata by default: `attachTcRmtcRow(s)` (MRN, SA), `attachPathListRow(s)` (IPR), `attachmentsFromDocuments` (Machine, Task chat), `enrichQcItemsWithDocuments` (QC). Invoice Receiving passes `{ metadata: true }`.
- A file name on the module record without an active `documents` row is not shown (it cannot be replaced or removed).
- **Safety net:** if a record's file column is still empty (for example, the backfill has not run or failed), its active `documents` rows are used instead, so old files never disappear from screens.

## 15. Migration and backfill

Both are safe to run more than once.

| Step | Runs | Does |
|------|------|------|
| `createDocumentsTable()` (`lib/documents/documents.table.js`) | **Every boot** (`initDB.js`, permanent) | Creates `documents` if missing, adds `documents.uuid` + unique index, and adds `tc_file` / `rmtc_file` (`VARCHAR(60)`) or `doc_files` (`JSONB`) for every module in `DOC_FILE_LINKS`. Skips missing tables. |
| `migrations/v5.0.0/docFileBackfill.js` | **Auto** on every boot while the version is 5.0.0 (`runVersionMigrations()`); safe to re-run | See the steps below. |

Columns are created from the registry on every boot, not by a one-time migration. A module added later gets its column on the next restart, even after `runVersionMigrations()` is turned off.

**Backfill steps (one transaction, safe to re-run)** — `migrations/v5.0.0/docFileBackfill.js`

Covers all seven `DOC_FILE_LINKS` modules (`OLD_PATHS` matches each key). Summary:

0. Legacy `documents` table (numeric `id`) → `uuid` PK (`VARCHAR`), folder-only `doc_path` where needed.
E/F. Active rows normalised; module `doc_files` / slot columns rebuilt from `documents`.
D. Orphan file names on module rows removed if no active `documents` row.
C. Empty module columns filled from active `documents`.
B. Still-empty records: legacy paths → new `documents` rows (disk must exist).
G. Drop legacy path columns on MRN, Stock Adjustment, `task_chat.attachments`.

Only empty module file columns are filled from B/C; re-run skips work already done.
Module columns are written only when the value changes, so later boots do nothing and print nothing.
Log: `✅ [v5.0.0] documents → <n> file(s) moved, <n> record(s) updated (module files/records: …), <n> missing on disk` — plus a cleaned-count line when orphan names are removed.

> ⚠ **Step G drops columns.** A legacy path whose file was not on disk is lost once its column is dropped. Back up the DB first; to keep the old columns, remove `dropLegacyPathColumns(q)` from the backfill.

It stops by itself after the next version bump (only the current version folder runs).

## 18. Upload flow — end to end

```
1. Screen          picks file(s) + optional remark per file
                   FormData: attachments | tc / rmtc | doc_<spec_id> | files, + file_remarks / doc_remarks / tc_remark / rmtc_remark
2. Route           docUpload(MODULE)          type + size check, saved as uploads/<module folder>/<uuidv7>.<ext>
3. Controller      mapMulterFilesWithRemarks(req) → [{ file, docPath, remark }]
                   moduleDocuments(MODULE).saveFiles(recordId, entries, req)
                   (or upsertTcRmtcSlot / syncPathsFromList / syncAttachmentList / persistQcSpecDocument)
4. Service         ONE transaction:
                     INSERT documents (uuid = <uuid>.<ext>, doc_path = folder, doc_type, doc_size KB, remark,
                                       mod_type, mod_ref, created_by, created_by_name)
                     add <uuid>.<ext> to the module record (doc_files JSONB, or tc_file / rmtc_file)
5. Read            module record → names → path = folder + name; remark / uploader from documents by uuid
6. Screen          file link = FILE_BASE_URL + /uploads/<folder>/<uuid>.<ext>, "Remark: …" under it
```

| Action | What happens |
|--------|--------------|
| **Upload** | New `documents` row + name added to the module record |
| **Replace** | New file saved first, then the old row → `status = false` and its name swapped out (old file stays if the new one is missing) |
| **Remove** | Row → `status = false`, name removed from the module record. Row and file are never deleted |
| **Remark only** | `documents.remark` updated; empty remark clears it |
| **Old path whose file is gone** | Skipped with a log warning — the rest of the save still works |

| Module | Field name | Saved via |
|--------|------------|-----------|
| MRN / Stock Adjustment | `tc`, `rmtc` + `tc_remark`, `rmtc_remark` | `upsertTcRmtcSlot` |
| QC Check | `doc_<spec_id>` + item `document_remark` | `persistQcSpecDocument` |
| In-Process Request | `attachments` + `doc_remarks` | `syncPathsFromList` |
| Invoice Receiving | `attachments` + `file_remarks`, `existing_paths` | `syncDocumentPaths` |
| Machine Master | `attachments` + `file_remarks`, `remove_attachment_ids` | `syncAttachmentList` |
| Task chat | `files` + `file_remarks` | `moduleDocuments("tasks").saveFiles` |
