## 1. Reassign — job card dropdown (In Process Request)

### Problem

- Reassign needed the same business idea as Issue Request (wire already on the coil; pick a target job card), but the first implementation loaded **all open job cards** in the browser and called **`production-mapping` once per distinct FG item** (~200+ XHRs on dropdown open, many 404s where mapping was missing).
- A separate **RM Wire** dropdown was added briefly; product rule is **one control**: job card only, wire = coil.

### Solution

| Layer | Behaviour |
|-------|-----------|
| **UI** | `UpdateCoilStatusForm.js` — consumed qty → **Job card** `SearchableSelect` only |
| **Wire on save** | `reassign_rm_item_code` and machine lock use **`coil.item_code`** (no user wire change) |
| **List source** | Frontend calls **`inProcessRequestService.reassignJobCards`** once per coil/search (client cache for pagination) |

### Eligible job cards (server logic)

1. Read coil **`rm_item_code`** (wire).
2. **`findApprovedFgItemsForRmWire`** — one SQL: all **approved** production rows whose `rm_items` include that wire.
3. **`loadMappedPrdRunJc`** — open job cards from ERP.
4. Keep rows whose FG key (`itemdcode` / `item_code`) is in the allowed set.
5. **Exclude** current/source job card (`exclude_pjobcardno`).
6. Set **`_isPrimaryProd`** when FG matches the source job card’s FG; sort primary first.
7. Apply search + page slice.

### Permissions (matches Issue Request SP1)

| User | Job cards in dropdown |
|------|------------------------|
| Normal (no **Issue RM — Mapped Select**) | Only **same production item** as source JC (`primaryOnly` on server) |
| SP1 (`issue_rm_mapped`) | Same production **plus** other FGs that map the same wire |
| Super Admin | Same as SP1 (full eligible set) |

Save-time rules unchanged: **`assertConsumeReassignRules`** in the IPR controller still validates target JC, machine, and wire mapping (normal users: target wire must be **priority-1** mapped on that JC).

## 2. Backend — `reassign-job-cards`

### Problem

Client-side filtering required N calls to **`/issue-requests/production-mapping`** (one per FG in the open JC list), which was slow, noisy in Network tab, and error-prone.

### Solution

| Item | Detail |
|------|--------|
| **Route** | `POST /api/rmstore/in-process-requests/reassign-job-cards` |
| **Auth** | `authenticate` + `accessControl("rm_in_process_request", "view")` |
| **Controller** | `getReassignJobCards` in `inProcessRequest.controller.js` |
| **Model helper** | `findApprovedFgItemsForRmWire` in `productionMaster.model.js` |
| **Reuse** | `loadMappedPrdRunJc`, `filterPrdRunJcBySearch`, `toPrdRunJcPickerRow`, `slicePage` from `erpItems.js` |

**Request body (main fields):** `rm_item_code`, `source_pjobcardno`, `exclude_pjobcardno`, `search`, `page`, `limit`.

**Response:** Picker rows (`id`, `label`, `sub`, …) plus **`_isPrimaryProd`** for dropdown styling.

## 5. IMS Store In — allow QC Hold boxes

### Problem

Store In treated boxes as **sellable** only (`in hand` **and** `qc_hold_id IS NULL`). Boxes on QC Hold could not appear in Pending, could not be scanned (or tray-scanned), and batch scan returned *"Box is on QC hold…"*. Business need: put held material on a rack without releasing the hold.

### Rule

| Action | QC Hold boxes |
|--------|----------------|
| **Store In** | **Allowed** — set `location_id` / `in_uid` only |
| **QC status** | **Unchanged** — `qc_hold_id` is not cleared or rewritten |
| **Forwarding Note** | Still excluded (`sqlBoxSellable`) |
| **Store Out** | Still rejected (`isBoxOnQcHold` in out-entry scan validation) |

### Fix (backend only, minimal)

| Location | Change |
|----------|--------|
| `inwardScanRejectMessage` | Removed the QC Hold–specific reject message |
| `batchScanInwardBoxes` | If sellable lookup misses but the box is **in hand** (incl. QC Hold), accept the scan |
| `findPackingAreaBoxesByTrayId` | `sqlBoxSellable` → `sqlBoxInHand` (tray Store In) |
| `packingAreaList` `PACKING_AREA_WHERE` | `sqlBoxSellable` → `sqlBoxInHand` (Pending list) |
| `isBoxEligibleForInward` | Uses `isBoxInHand` instead of `isBoxSellable` |

`updateBoxesAfterInward` already updates only `location_id` + `in_uid` — no `qc_hold_id` write.

Shared helpers left alone so other flows stay safe:

| Helper | Still excludes QC Hold |
|--------|-------------------------|
| `findInHandBoxesByScanCodes` | Still `sqlBoxSellable` (Manage Tray / some Out Entry scans) |
| `findSellableBoxesByTrayId` | Still sellable (Store Out tray) |
| Forwarding Note box queries | Still `sqlBoxSellable` |
| `validateOutEntry*ScannedBoxes` | Still `isBoxOnQcHold` reject |

|------|------|
| Batch scan | `backend/.../inventory-inward/controllers/inventoryInward.controller.js` |
| Pending list | `backend/.../inventory-inward/utils/list/packingAreaList.js` |
| Reject msg + tray boxes | `backend/.../box/models/box.model.js` |
| Eligibility helper | `backend/.../box/utils/inventory/boxInventory.js` |
