## v4.5.0 — Engineering Process Master · Machine Master

### 8 Oct 2026

**Summary.** New **Engineering** masters: **Process Master** (hierarchy + stage) and **Machine Master** (process link, duration in seconds, JSON attachments). Same IMS create → approve → edit flow, audit fields, list shortcuts, and Approval Status toggle. Tables use `eng_` prefix; soft delete via `is_deleted`.

| Topic | Summary |
|-------|---------|
| **Process Master** | Self-referencing tree: MASTER / SUB / SUB_SUB + `parent_id` |
| **Process stage** | START / MID / END (default MID); only one active START and one active END |
| **Process pattern** | Optional regex; validated on save |
| **Machine Master** | Name, unique number, one approved process, speed, duration, make/model/remark |
| **Duration** | Column `duration` (seconds); FE Sec/Min/Hour convert on save/edit |
| **Attachments** | JSONB on machine row — slim keys only (`id`, `file_name`, `path`, `size`) |
| **Speed** | Stored as typed text (e.g. `10`), not `10.0000` |
| **Approval** | Status toggle on **create only**; edit/approve show footer-hint banner + buttons (IMS style) |
| **Upload folder** | `uploads/eng/machine` |
| **Helper** | `/process-master/helper` — IMS-style map in `helperViews.js` (which page + which action); FE `helperPerms(MODULE, action)` |
| **Nav / portal** | Engineering Masters: Process + Machine only (Product Master removed) |
| **API** | `/api/engineering/process-master/*`, `/api/engineering/machine-master/*` |

## 1. Process Master

### What / why / outcome

| | |
|--|--|
| **What** | `eng_process_master` with hierarchy, stage, multi-machine flag, optional pattern; list shows Parent > Child path. |
| **Why** | Engineering needs a process tree and unique START/END for job-card flows. |
| **Outcome** | Create → Approve → Edit like IMS; parent dropdown filtered by type; duplicate START/END rejected. |

### Rules

| Rule | Behaviour |
|------|-----------|
| MASTER | `parent_id` null |
| SUB | Parent must be MASTER |
| SUB_SUB | Parent must be SUB |
| START / END | At most one active (`is_deleted = false`) each |
| Pattern | Empty OK; if set, must be valid `RegExp` |
| Timestamps | Create → `created_*`; Approve → `approved_*`; Edit → `updated_*`; create/edit+approve → `updated_*` + `approved_*` |

### Key files

| Layer | Path |
|-------|------|
| Table | `backend/.../tables/process/process_master.table.js` (`multi_mc` flag) |
| Model / API | `backend/.../modules/process-master/{models,controllers,routes}` |
| UI | `frontend/src/apps/engineering/modules/process-master/{Page,ProcessModal}.js` |
| App route | `frontend/src/app/engineering/dashboard/master/process-master/page.js` |

## 2. Machine Master

### What / why / outcome

| | |
|--|--|
| **What** | `eng_machine_master` linked to one approved process; duration in seconds; attachments in `attachments` JSONB. |
| **Why** | Machines belong to processes; duration units vary on UI but storage stays consistent. |
| **Outcome** | Unique machine number; multipart upload via shared IMS upload middleware; open attachment uses backend `FILE_BASE_URL`. |

### Attachment JSON shape

```json
[{ "id", "file_name", "path", "size" }]
```

## v4.5.1 — RM Store · IPR rejection → Store In (Unassigned)

**One line:** IPR-rejected coils still go to RM Rejection as before, and they also show in Store In → Unassigned (source **IPR REJECTION**) so you can rack them with normal Store In—no separate Receive step.

| Area | Change |
|------|--------|
| **IPR / RM Rejection** | Supplier + source (job card, machine, FG, OUT) on Pending, Register, and drawers — unchanged flow for gate pass. |
| **Store In · Unassigned** | Coils with `status = rejected` and `ipr_uid` appear in By MRN and By Coil; old unlocated IPR rejects included. |
| **Source label** | `coilSourceSql` → **IPR REJECTION**; UI badge on Store In list. |
| **Store In · save** | Scan + save allow IPR-rejected coils (`InwardModal` + backend `INWARD_STATUS_SQL` / `resolveCoilsForInward`). |
| **Not changed** | IPR pending Receive for consume/return; no rejection Receive modal; QC-fail rejected coils still blocked from Store In. |

### Files (main)

- `backend/.../lib/utils/mrnPortalCoilSql.js` — `iprRejectedCoilSql`, coil-area eligibility
- `backend/.../coil/models/coil.model.js` — source, filters, inward location updates
- `backend/.../inventory-inward/` — controller validation, `inwardRegister.js`
- `frontend/.../inventory-inward/` — `Page.js` (badge), `InwardModal.js` (scan + save)
