### 6. Forwarding Note — Edit / Approve Fix

**Problem:** The edit form displayed incorrect packing (live FIFO preview) while quantity and print output remained correct.

**Cause:** Background stock load populated `selected_boxes` and overwrote the `original_breakdowns` display.

**After fix:**
- All saved packing lines appear on edit and approve (same `item_dcode + schno`)
- Saving without item changes preserves existing DB rows
- Saving with quantity or box edits triggers normal FIFO recalculation

### 7. Forwarding Note — FIFO Rules

**Sort (FE + BE):** `packing_number` ASC → full/loose → `box_uid` ASC  
*(Loose Priority toggle reverses full/loose order)*

**Pool:** Physical finished goods minus other forwarding note reserves  
- Add: all reserves block selection  
- Edit/Approve: `exclude_fuid` includes the current note’s own reserve  

**Pick:** Oldest packing first · contiguous prefix · full boxes only · no gaps · balance cap on schedule rows

**Multi-row same item:** Row order is exclusive — no duplicate `box_uid`

**Save:** Packing-wise rows in `ims_forwarding_note_item_wise` act as reserves (consumed later by Store Out)

**FIFO recalculates on edit only when the user changes quantity, boxes, or loose priority**

| Check (BE) | Blocks |
|------------|--------|
| `assertForwardingItemsWithinRemaining` | Over-reservation |
| `assertNoDuplicateSelectedBoxes` | Same box on two rows |
| `assertScheduleDispatchWithinBalance` | Exceeding schedule balance |

**FIFO reference files:** `utilHelper.js`, `forwardingAvailableStock.js`, `forwardingNoteItemsWrite.js`

### 8. Forwarding Note — Live Bill Timing

A live bill is shown only when **bill calendar day ≥ FN created calendar day** (time-of-day ignored). Same day is allowed; a bill from an earlier day (e.g. bill on 20th, FN on 25th) is not. Attached DB bills always appear in the list and dropdown.

---

### 9. Forwarding Note — Bill List and Print

**List (item-wise):** Live invfnote bills appear on each matching line (same `billno` on multi-item bills is allowed). Exclusivity is per invfnote `uid`, not per bill number.

**Dropdown:** Match key — **super admin:** `acc-item` (e.g. `3016-19232`); **other users:** `acc-item-packing` (e.g. `3016-19232-40359`). Saved `bill_no` is always listed. Live bills: green when bill day is on or after FN created day. Sub-line shows match key + Item · Pack · Qty.

**Print:** Uses only **`ims_forwarding_note_item_wise.bill_no` / `bill_dt`** (saved via Save Bill). Live list bills (`billno` merge) are **not** used on print. If no bill is saved, the print footer is blank.

**Same bill on multiple lines**

| Context | Rule |
|---------|------|
| **Live list** | Each invfnote `uid` may appear live on one unsaved row only (prevents incorrect duplicate live display) |
| **Save Bill** | Saving the same `bill_no` on two or more lines is **allowed** |
| **View colour** | Saved DB bill → **blue**; live only → green / orange (IMS status) |

**Fix:** Removed reference to `fnm.timestamp`; use `fnm.created_at` (column did not exist).

| File | Change |
|------|--------|
| `forwardingNoteList.js` | UID-based live merge, dropdown attached bill, match key, `created_at` |
| `forwardingNoteItem.model.js` | `created_at AS timestamp`, date filter |
| `forwardingNote.controller.js` | Bill dropdown API, `approved_at = updated_at` |
| `ForwardingPage.js` | Saved bill `is_green`, match hint under dropdown |

### 10. Modal / Drawer — Tab Focus Trap (Global)

**Problem:** With a drawer or center modal open (Delete, confirm, detail), pressing Tab moved focus to background list items and buttons.

**Solution (centralized):**

| Component | Role |
|-----------|------|
| `overlayFocusGuard.js` + `OverlayFocusGuard` (`app/layout.js`) | App-wide Tab trap and background `inert`; focus stays within the top overlay (highest z-index) |
| `Drawer.js` | Portal + `data-app-overlay-root`; scroll lock; ESC / Ctrl+S / Ctrl+P unchanged |
| `OverlayModal.js` | Center modals — portal to `document.body` + `data-app-overlay-root` |

**Covered automatically:** All forms using `Drawer` (Edit, Add, Approve, Forwarding Note, Task, RM Store, etc.) and shared center modals.

**Updated center modals:**

| File | Change |
|------|--------|
| `DeleteModal.js` | Uses `OverlayModal` |
| `GlobalDetailModal.js` | Uses `OverlayModal` |
| `DepartmentModal.js` / `DesignationModal.js` | Uses `OverlayModal` |
| `StickerRemoveConfirmModal.js` | Uses `OverlayModal` |
| `SchedulePlanRemoveConfirmModal.js` | Uses `OverlayModal` |
| `MrnStickerRemoveConfirmModal.js` | Uses `OverlayModal` |
| `NotificationLogViewModal.js` | Uses `OverlayModal` |
| `apps/task/lib/ui/common/DeleteModal.js` | Re-exports shared `DeleteModal` |

**Behaviour:**
- Tab cycles only within the active overlay
- SearchableSelect dropdown portal is excluded (Tab works inside the dropdown)
- When file preview is open, ESC closes preview first, then the drawer/modal
- Delete modal z-index **1100**; Drawer **1050** — Delete appears above Drawer

**Unchanged (no business logic impact):** Add · Edit · Approve · Delete · FIFO · Bill save/list/print · ESC · Ctrl+S · Ctrl+P

**Not yet covered (edge cases):** Custom `fixed inset-0` popups that do not use `OverlayModal` (e.g. sticker preview, QR scanner, dashboard builder). New center modals should use `OverlayModal`.
