## v4.4.6 — PWA icon badge · office-network gate · IMS shortage · RM dropdown color logic · IPR reassign picker

### 3 Oct 2026

**Summary.** Installed PWA home-screen icon shows **unread inbox count** (blank at 0, then 1, 2, 3…). On the **internal live domain**, if the device cannot reach the **inside backend**, users see a full-screen **Connect to the office network** message (proper English) instead of a broken app or repeated auto-checks. **Try again** runs one manual check only. External portal (`devout…`) is unchanged. **IMS Shortage** keeps the same add/edit/bulk/master flow; each row stays on **`month`**; list **Default** report now shows **current calendar month** only (past months via **Custom** + month/date filter). **RMstore:** documented **Issue Request RM Wire** vs **IPR Reassign job card** dropdown **color rules** (no “Primary/Secondary” labels in UI). IPR **`reassign-job-cards`** uses production **`rm_items` order** for row highlight and stable FG lookup.

| Topic | Summary |
|-------|---------|
| **Icon badge** | Badging API: `setAppBadge(n)` / `clearAppBadge()` when unsupported — no errors |

## 1. PWA icon badge

### Behaviour

| Unread | Icon |
|--------|------|
| 0 | No badge (cleared, never shows “0”) |
| 1+ | Number on home-screen / taskbar icon (OS-dependent; needs installed PWA + notification permission for best results) |

### Flow

1. Inbox row saved → push includes **`unread_count_all`** (total) + per-app `unread_count`.
2. **Bell:** `loadUnreadInbox` with `getInboxAppFilter(pathname)` — home = all, app routes = that `app_type`.
3. **PWA icon:** `syncGlobalIconBadge()` — always `/inbox/unread-count` without filter.
4. **Logout:** no badge/inbox reset; push can still update icon when app closed.
5. **`sw.js`** cache **v36**; stale list loads ignored via `loadInboxSeq`.

## 2. Office network gate (internal domain)

### Rule

| Situation | Result |
|-----------|--------|
| On **company / office network** (inside backend reachable) | App works normally |
| On **wrong network** (mobile data, other WiFi) while on internal URL | Full-screen gate + hint for external portal |
| **External** portal domain | No gate (remote Cloudflare flow) |

Detection is **not GPS** — only “can this browser reach the **inside** API?” (`companyNetwork.js` → `/api/version`). Timeout counts as unreachable.

### UX

- Copy: **Connect to the office network**, body + Cloudflare external-portal hint (`messages.js`).
- Button: **Try again** → one check, **Checking connection…** while that request runs.
- No background loop every few seconds.
- Successful API while gate was open clears overlay (`NETWORK_REACHABLE_EVENT`).

### Service worker (site won’t load)

When **navigate** fetch fails and there is no cached app shell, SW redirects to **`/offline-vpn-reminder.html`** with the same English text (and optional `external_host` query).

### Key files

| Path |
|------|
| `frontend/src/platform/utils/auth/companyNetwork.js` |
| `frontend/src/platform/hooks/auth/useCompanyNetworkGuard.js` |
| `frontend/src/ui/common/system/CompanyNetworkGate.js` |
| `frontend/src/platform/utils/global/messages.js` |
| `frontend/public/offline-vpn-reminder.html` |
| `frontend/public/sw.js` |

### Limitation

If the **internal hostname does not resolve at all** and the PWA was never installed/updated on office network, the browser may still show **“This site can’t be reached”** before any app code runs. Remote users should use the **external portal** link.

## 7. RMstore — dropdown color logic (Issue Request vs IPR Reassign)

Reference for operators and devs: **how row colors appear** after **Job Card → RM Wire** (Issue Request) or **Reassign → Job card** (IPR). There are **no “Primary” / “Secondary” text labels** in either dropdown — only background + left border (+ optional bold).

### 7.1 Issue Request — Job Card, then RM Wire

**Flow**

1. User picks **Job Card** on a breakdown row.
2. Frontend loads **approved Production Master** for that JC’s FG item → **`mapped_rm_items`** = `rm_items` JSON **in saved array order** (position 1 = priority-1 wire for save rules).
3. **RM Wire** `SearchableSelect` options depend on **`issueRmSelectionMode(user)`** (`rmstoreSpecialPermissions.js`):

| Mode | Who | RM Wire dropdown |
|------|-----|------------------|
| `first` | Normal user | **Disabled** — auto-select **first** mapped wire only |
| `mapped` | SP1 (`issue_rm_mapped`) | Only **mapped** wires (production list), no full-catalog color styling |
| `all` | Super Admin | **Full ERP RM catalog** (~5000) + mapping flags |

**Color (Issue Request only when mode = `all`)**

| Step | Logic |
|------|--------|
| List build | `fetchRmWireOptions(rmOpts, …, { mappedItems: row.mapped_rm_items })` in `issueRmWireSelect.js` |
| Flag | Each row: **`_isMapped`** = wire key (`dcode` or `code`) exists in **`mapped_rm_items`** |
| Sort | Mapped rows **first**, order = **production array order**; unmapped ERP wires below |
| Paint | `IssueRequestModal.js` → `getOptionStyle` / `getOptionClassName` **only if** `rmSelectionMode === "all"` **and** `item._isMapped` |
| Palette | **`getSuperAdminRowRmColor(breakdownRowIndex)`** — Row #1 indigo, Row #2 emerald, Row #3 amber, … (same soft bg + `3px` left accent for **all** mapped lines on that grid row) |

**Meaning:** Color = “this RM wire is **on the production map** for the selected job card,” shown only when Super Admin searches the **full** wire list. It is **not** a different color per wire sequence slot (2nd mapped wire uses the **same** row palette as 1st mapped wire).

**Labels:** `labelKey="item_code"`, `subLabelKey="sub"` (description); `showDuplicateSubLabel` may show identical title/sub when code matches desc.

### 7.2 IPR — Update Coil Status → Reassign → Job card

**Flow**

1. Coil **RM wire is fixed** (`coil.item_code`); user enters consumed qty and picks **target Job card** only.
2. **`POST …/in-process-requests/reassign-job-cards`** returns eligible open JCs whose FG maps the coil wire (permissions same idea as Issue Request SP1).
3. Frontend: `fetchReassignJobCards` caches full filtered list, **slices 50/page** for `SearchableSelect`; `preserveApiOrder`; primary rows sorted first on server.

**Color (IPR Reassign)**

| Step | Logic |
|------|--------|
| Server | For each JC: **`is_primary`** = `1` iff coil’s wire is **index 0** (1-based seq **1**) in that FG’s approved **`rm_items`**; also **`_isPrimaryProd`** (same flag for UI) |
| Lookup | Production row resolved by **both** `item_dcode` and `item_code` keys; optional **`rm_item_dcode`** on request body |
| Paint | `UpdateCoilStatusForm.js` → highlight when **`is_primary === 1`** or **`_isPrimaryProd`** via `getSuperAdminRowRmColor(0)` (soft bg + left border) |
| Text | **No** `"Primary · …"` or `"Secondary"` in `sub` — picker **`label` / `sub`** stay normal JC lines |

**Permissions vs highlight**

| User | List scope | Typical highlight |
|------|------------|-------------------|
| Normal | Same FG production as source JC only | Often **all visible JCs share one FG** — if wire is priority-1, **many rows** may look highlighted (same mapping rule) |
| SP1 / Super Admin | Other FGs that map the same wire | Only JCs where wire is **1st in `rm_items`** get highlight |

Save unchanged: normal users still need **priority-1** wire on target JC (`assertConsumeReassignRules`).
