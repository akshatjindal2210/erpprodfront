### IMS — Invoice Receiving (local on Gate Entry)

**Before (v4.3.10):** Pending / Register / update / delete went through ERP internal API `invreceiving`. Gate Entry was only used to filter pending to gate-registered bills.

**After (v4.4.1):** Invoice Receiving is fully local on `ims_gate_entry`. No `invreceiving` calls for list, update, or delete.

#### Gate Entry columns

| Column | Type | Purpose |
|--------|------|---------|
| `invoice_matched` | `BOOLEAN NOT NULL DEFAULT false` | `false` = IR Pending · `true` = received (Register / Approve path) |
| `receiving_file` | `TEXT` | Attachment paths JSON `{"0":"a.pdf","1":"b.png"}` under `uploads/ims/invoice-receiving/` |
| `receiving_meta` | `TEXT` | Audit JSON: remarks, approved, approved_by/at, uploaded_by/at (+ optional display fields from import) |

Schema: `backend/.../tables/gate-entry/gate_entry.table.js` (CREATE + `patchCol` on boot).

#### Tabs / APIs

| Tab / action | Behaviour |
|--------------|-----------|
| **Pending** | Gate Out rows where `invoice_matched = false` |
| **Register** | `invoice_matched = true` **and** `receiving_file` present; date filter = Gate **`created_at`** (IST) |
| **Receive / Edit / Approve** | `POST /update` → save file + meta on matching Gate row by `bill_no`; sets `invoice_matched = true` |
| **Delete** | Clears `receiving_file` / `receiving_meta`, sets `invoice_matched = false` → back to Pending |
| **Pending Approve-ready** | FE merges unmatched pending + all matched-but-not-approved (no date on merge) in one `Promise.all` paint |

Approve vs receive differs only inside `receiving_meta` (`approved` / `approved_by` / `approved_at`).

#### Gate Entry isolation

Invoice Receiving **must not** change Gate business audit fields:

| Touched by IR | Not touched by IR |
|---------------|-------------------|
| `invoice_matched`, `receiving_file`, `receiving_meta` | `bill_no`, `bill_dt`, transporter, vehicle, remarks |
| | Gate `approved` / `approved_by` / `approved_at` |
| | **`updated_at` / `updated_by`** |

#### One-time ERP → Gate backfill

Old ERP register rows **with attachments** → Gate columns (match on `bill_no`).

| Item | Path |
|------|------|
| Script | `backend/src/backfills/importErpInvoiceReceivingToGate.js` |
| Wired in | `backend/src/backfills/index.js` — `await safe("IR ERP → gate", …)` |

**Deploy:** restore live DB → start backend once → check IR Register → **comment out** that `await safe(...)` line so it does not run again. Uncomment later only to re-import.

Idempotent: skips Gate rows that already have `receiving_file`. Bills with ERP file but no Gate Out row are skipped (`noGate` in log).

#### Display-only IMS call

Customer name on IR lists still enriched from live **`invmnote`** (same idea as Gate Entry register). Receiving data itself is not on ERP.

#### Files

| Layer | Path |
|-------|------|
| Schema | `backend/.../gate-entry/gate_entry.table.js` |
| Model | `backend/.../gate-entry/models/gateEntry.model.js` |
| IR controller | `backend/.../invoice-receiving/controllers/invoiceReceiving.controller.js` |
| IR payload helpers | `backend/.../invoice-receiving/utils/buildInvReceivingUploadFilter.js` |
| Backfill | `backend/src/backfills/importErpInvoiceReceivingToGate.js` + `backfills/index.js` |
| FE list | `frontend/.../invoice-receiving/Page.js` |
| FE service | `frontend/.../ims/lib/services/invoiceReceiving.js` |

3. Pending → Receive → Approve → Register → Delete → Pending
4. Confirm Gate Entry row `updated_at` unchanged after IR actions

| Piece | Location |
|-------|----------|
| Config + dispatch | `backend/.../templates/moduleNotify.service.js` |

| Message Logs (PWA) | `mst_push_delivery_log` (+ WhatsApp rows from activity) |

#### Behaviour

| Topic | Detail |

| In-app delivery | `saveInboxAlert` + socket; OS popup via `taskNotifySocket` / `handleOsNotification` |

| Message Logs (task PWA) | Unchanged — per device, Received/Read tracking |
| Push failures | Expired subscription (410/404) removed silently; no Failed row if inbox already saved |
| Push statuses | sent / failed / received / read only (no skipped on push log) |
