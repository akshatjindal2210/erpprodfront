# A. IMS Box: Journey Filter Include / Exclude Zone

Journey search on **IMS → Boxes** returns mixed rows (Dispatch, Packing Area, Location, QC Area). Users can now narrow that list **client-side** without another API call.

|           |                                                                 |
|-----------|-----------------------------------------------------------------|
| **UI**    | IMS → Boxes → Journey filter strip                              |
| **API**   | **No change** — same `POST /api/boxes/` journey filter          |
| **DB**    | No schema change                                                |
| **Scope** | Box list — Journey mode only                                    |
| **Dates** | **8 Sep 2026**                                                  |

---

## Problem

Journey filter traces a packing / box / item / job card across the full DB. One search often returns boxes in **different stock zones** at the same time:

| Zone (Location column) | `getBoxStockZone()` |
|------------------------|---------------------|
| Dispatch               | `dispatched`        |
| Packing Area           | `packing_area`      |
| Rack / shelf code      | `in_store`          |
| QC Area                | `qc_hold`           |

Before this change, the user had only **Quick Search** (text) to narrow results. There was no simple way to say “show only dispatched” or “hide packing area rows” after a journey load.

---

## Why client-side only (no backend change)

| Reason | Detail |
|--------|--------|
| Journey API already returns all matching boxes | Re-filtering by zone is a **view** concern, not a new DB query |
| Avoid regression | `appendBoxJourneyCondition` / `logJourneyFilter.js` unchanged |
| Instant UX | Dropdown applies immediately on already-loaded rows |
| Existing date-range mode untouched | Zone filter is hidden unless Journey is applied |

Backend zone logic (`boxInventory.js`, `getBoxStockZone`) was already correct for row display. This feature **reuses** that same classification for filtering.

---

## What changed

### 1. `frontend/src/apps/ims/modules/box/boxTableVisuals.js`

**Added**

| Export | Purpose |
|--------|---------|
| `JOURNEY_ZONE_FILTER_OPTIONS` | Dropdown labels + values (`include:dispatched`, `exclude:packing_area`, …) |
| `applyBoxJourneyZoneFilter(rows, filterValue)` | Filters an array of box rows by zone |

**Filter value format**

```
{mode}:{zone}
```

- `mode` → `include` | `exclude`
- `zone` → same keys as `getBoxStockZone()`: `dispatched`, `packing_area`, `in_store`, `qc_hold`

**Logic**

```
For each row:
  zone = getBoxStockZone(row)
  if mode === "include"  → keep row when zone === category
  if mode === "exclude"  → keep row when zone !== category
  if filter empty        → return all rows (unchanged behaviour)
```

`getBoxStockZone()` itself was **not** modified — single source of truth for zone classification.

---

### 2. `frontend/src/apps/ims/modules/box/Page.js`

**State**

| State | Default | When cleared |
|-------|---------|--------------|
| `journeyZoneFilter` | `""` (All zones) | Reset · Journey cleared · Switch back to date-range search |

**UI**

- When `appliedJourney` is set (Journey mode), a **Zone** `<select>` appears next to the Journey text field.
- Uses existing `DateRangeFilter` `extraFilters` + `variant: "quick"` (indigo = client-side filter).
- `onExtraFilterChange` updates state and resets `displayLimit` to 100.

**Data flow**

```
fetchBoxes()  →  allRows  (API, unchanged)
                    ↓
         applyBoxJourneyZoneFilter  (only if journey + zone filter set)
                    ↓
         applyClientSearch  (Quick Search, unchanged)
                    ↓
         sortRowsByKey  →  filteredRows  →  table
```

**Reset behaviour**

- **Reset** button → clears journey + zone filter + dates (same as before + zone).
- **Search** with empty Journey → exits journey mode and clears zone filter.
- Date-range listing → Zone dropdown **hidden**; no effect on normal list.

## User-visible behaviour

| Zone filter selection | Result |
|-----------------------|--------|
| All zones (default) | Same as before — all journey matches shown |
| Include Dispatch | Only rows where zone = `dispatched` |
| Exclude Dispatch | Hide dispatched; show packing / location / QC / other |
| Include Packing Area | Only `packing_area` rows |
| Exclude Packing Area | Hide packing area rows |
| Include Location | Only `in_store` rows (rack/shelf assigned) |
| Exclude Location | Hide in-store rows |
| Include QC Area | Only `qc_hold` rows |
| Exclude QC Area | Hide QC hold rows |

Rows with zone `other` are included on **Exclude** filters and excluded on **Include** filters (they do not match any named category).

# B. List pages — Ctrl+F toggle (Quick Search ↔ table)

**Date:** 9 Sep 2026

### Before

`Ctrl+F` / `Cmd+F` always focused the list filter strip (Quick Search). Browser find is overridden. There was no way to jump back to the table with the same shortcut.

### After

| Focus | Shortcut | Result |
|-------|----------|--------|
| Table (or outside search) | `Ctrl+F` | Focus Quick Search (select text) |
| Quick Search / filter strip | `Ctrl+F` | Blur search; select first data cell in the visible list table |

Blocked while a drawer or dialog is open (unchanged).

### Implementation

Single-file change — logic lives in the existing global hotkey only.

| File | Change |
|------|--------|
| `frontend/src/ui/common/list/ListPageFilterFocusHotkey.js` | If focus is inside `[data-list-page-filter-strip]`, blur and `mousedown` the first `td` (skip checkbox column). Otherwise call `focusFirstListPageFilter()`. |

No API, schema, or page-specific wiring. Applies to every list that uses `ListPageFilterStrip` + `DataTable` (`data-list-table-root`).

### Test

1. Open any list page with Quick Search + table.
2. `Ctrl+F` → cursor in Quick Search.
3. Type a filter → `Ctrl+F` again → first row cell selected; arrow keys work on the table.
4. `Ctrl+F` again → back to Quick Search.

# C. Sticker Control — PRINT ALL order (1, 2, 3…)

**Date:** 9 Sep 2026

### Problem

Sticker Control table mein boxes **1, 2, 3 … 16** sahi order mein dikhte the, lekin **PRINT ALL** dabane par print **15, 14, phir 1, 2, 3…** jaise galat order mein aa raha tha.

### Root cause

| Step | Detail |
|------|--------|
| UI list | Frontend se sahi dikhta hai |
| Print | Backend dubara DB se boxes fetch karta hai (`findBoxesDetailed`) |
| Bug | Query mein **ORDER BY nahi tha** — PostgreSQL rows random / `box_uid` order mein bhej deta tha |
| Why wrong | `box_uid` (DB auto ID) hamesha sticker number (1, 2, 3…) ke barabar nahi hota |

### Fix (minimal — 1 line)

`backend/src/apps/ims/modules/box/models/box.model.js` → `findBoxesDetailed`:

```sql
ORDER BY COALESCE(
  NULLIF(regexp_replace(b.box_no_uid, '^.*_', ''), '')::int,
  b.box_uid
) ASC
```

`box_no_uid` ke **aakhri segment** se sort — e.g. `FG_26_41143_16_1` → **1**, `…_16` → **16**.

### Scope

| Area | Change |
|------|--------|
| Frontend | **No change** |
| Controller | **No change** |
| Backend | **1 line** in `findBoxesDetailed` |
| Affects | PRINT ALL, bulk sticker render, koi bhi flow jo `findBoxesDetailed` use karta hai |

### Test

1. Sticker Control → packing with 16 boxes open karo.
2. Table mein `FG_…_1` se `FG_…_16` order check karo.
3. **PRINT ALL** → print preview / printer pe **1, 2, 3 … 16** order verify karo.

# H. Dashboard Builder — session filters (`{{type}}`, `{{designationId}}`, `{{departmentId}}`)

**Date:** 9 Sep 2026

Available Filters chips from logged-in session (`req.user`). Not URL / not spoofable.

| Token | Resolves to | SQL form |
|-------|-------------|----------|
| `{{type}}` | Auth type (`admin`, `user`, …) | Quoted string |
| `{{designationId}}` / `{{designation_id}}` | `designation_id` | Unquoted int / `NULL` |
| `{{departmentId}}` / `{{department_id}}` | `department_id` | Unquoted int / `NULL` |

**Test query (`mst_users`)**

```sql
SELECT id, username, name, type, designation_id, department_id
FROM mst_users
WHERE status = 'active'
  AND type = {{type}}
  AND ({{designationId}} IS NULL OR designation_id = {{designationId}})
  AND ({{departmentId}} IS NULL OR department_id = {{departmentId}})
ORDER BY name
LIMIT 50
```

**Extensible:** BE `DASHBOARD_SESSION_STRING_FILTERS` one row + FE chip. Use `kind: "number"` for ids.

| File | Change |
|------|--------|
| `frontend/.../utils/widgetQuery.js` | Type / Designation ID / Department ID chips |
| `backend/.../query/widgetQuery.js` | Session filters (string + number) |
| `dashboard.controller.js` | `sessionIdentityFilterValues(actor)` merge |

No schema change. Existing widgets without these tokens unchanged.
