### PWA Push — Sent, Received, and Read tracking

**Added:**
- Every push notification is now tracked in three stages — Sent, Received, Read.
- Admin → Settings → Notifications → Logs shows these three columns.

**Sent:**
- Server delivered the notification (Google FCM / Mozilla). Timestamp: `sent_at`.
- Independent of user network — this is server-side.

**Received:**
- Notification appeared on the user's phone (tray / lock screen). Timestamp: `received_at`.
- Works on any network — mobile data, home Wi-Fi, office Wi-Fi.
- Counted after logout (service worker runs on device).

**Read:**
- User tapped the notification and opened the PWA. Timestamp: `read_at`.
- Counted only on company network.
- Tap from home / mobile data → Wi-Fi reminder page; read time is not saved.

**Difference:**
- Received = notification arrived on the phone (any network).
- Read = user opened the app (company network only).

**Flow:**
1. Server sends → status = sent
2. Notification appears on phone → service worker reports → status = received
3. User taps → on company network: read + app opens | otherwise: Wi-Fi reminder

**Logout:**
- Device subscription is not deleted on logout — push can still arrive after logout.
- To remove, use unsubscribe / unlink API.

### Company Wi-Fi check — On notification tap

**Note:**
- Company Wi-Fi is not required to receive a notification.
- This check runs only when the user taps a notification to open the app.

**Steps:**
1. Company backend ping (`GET /api/version`) — if response received, open app.
2. If ping fails, match public IP — if match, allow.
3. If both fail → "Connect to company Wi-Fi" page → user connects → Try again.

**Received report is separate:**
- Received can be reported on any network.
- If offline, queued and sent later.

**Bug fix:**
- Previously blocked with wrong IP even after ping succeeded.
- Now ping OK = directly allow.

**.env:**
- `PUSH_API_BASE_URL`, `PUSH_API_BASE_FALLBACKS`, `COMPANY_BACKEND_URL`, `COMPANY_PUBLIC_IP`

**Files:**
- `sw.js`, `offline-vpn-reminder.html`, `companyNetwork.js`, `CompanyNetworkGate.js`, `webPushSubscribe.js`

### IMS — Forwarding Note stock reserve fix *(4 Jul 2026)*

#### Same packing on two Forwarding Notes

**Problem:**
- The same packing number was saved on two different Forwarding Notes (e.g. FN 327 & 335).
- One physical stock assigned to two customers — risk of incorrect dispatch.

**Cause:**
- Stale screen, race condition, no packing-wise check,
- validation skipped on edit path, no re-check before approve.

**Fix:**
- Packing-wise validation, transaction + advisory lock, re-validate before approve.
- Legacy duplicate rows — must be fixed manually.

**Files:**
- `forwardingNoteItemsWrite.js`, `forwardingNote.model.js`, `forwardingNoteItem.model.js`, `forwardingNote.controller.js`, `forwardingAvailableStock.js`

#### Draft stock block — Only Approved notes reserve

**Problem:**
- Stock was blocked on draft save; two draft notes could overlap.

**Fix:**
- UI shows stock reduced only by Approved notes.
- On Save / Approve, all saved rows are checked — double booking blocked.

**New flow:**
- Draft save → other users still see full stock.
- Approve → stock is officially reserved.

**Note:** No DB migration. Fix legacy duplicate FN rows manually.

### Portal access — Domain-based (replaces public IP check) *(6 Jul 2026)*

**Change:**
- Removed public IP logic (`COMPANY_PUBLIC_IP=223.190.86.9`, `api.ipify.org`) from frontend and backend.
- Access is now decided by **portal domain**, not office public IP.

**Domains:**

| Portal | Domain | Users | Behaviour |
|--------|--------|-------|-----------|
| Internal (office) | `dev.jflbharat.com` | Office staff | PWA opens when office backend is reachable; otherwise office-network reminder |
| External (remote) | `out.dev.jflbharat.com` | Invited users (email + Cloudflare OTP) | Opens from any network — no IP / Wi-Fi check |

**Push notification tap:**
- **External portal** → app opens directly; read logged as external (`on_internal_domain: false`).
- **Internal portal** → backend ping (`GET /api/version`); if OK, open app and log read as internal.
- **Internal + backend unreachable** → office-network reminder page (suggests external portal for remote access).
- **Received** stage unchanged — works on any network.

**Removed:**
- `COMPANY_PUBLIC_IP` / `NEXT_PUBLIC_COMPANY_PUBLIC_IP` from `.env`
- `company_public_ip` from backend `config.js` and push payload
- IP fetch (`api.ipify.org`) from service worker and offline reminder page

- `frontend/src/core/utils/global/messages.js` — office-network copy updated
