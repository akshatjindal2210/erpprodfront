## RM Store — Stock Adjustment MRN receipt cap (`mrn_rm` + `mrn_rm_old`)

### 26 Sep 2026

| Topic | Summary |
|-------|---------|
| **Symptom** | Add (+) / Old **Load** or **Update** blocked while internal IMS shows higher line qty (e.g. **`3849_2`**: **`mrn_rm`** 1145 KG vs **`mrn_rm_old`** **`itrecpqty` 2790** + **`coils`** JSON summing to 2790). API error: *Add quantity exceeds remaining MRN receipt (0 of 1145 KG)* |
| **Cause** | Budget used live **`mrn_rm`** only; **`mrn_rm_old`** ignored. Bill **`totalqty`** (e.g. 10190) must not be the line cap. Edit UI could treat **`remaining_qty === 0`** as no save; later a bug let **total qty on edit climb with form input** (no real MRN ceiling) |
| **Business rule** | Per **`mrn_uid`**, max bookable = **internal IMS line receipt** for that UID. **Less than cap OK**; **more blocked**. Example cap **2790**; if **1145 KG** already in coils → **`remaining_qty` ≈ 1645** |

### Backend

| Topic | Summary |
|-------|---------|
| **Receipt cap** | **`mrn_rm_old`** row when present → **`max(itrecpqty, sum(coils JSON))`**; else **`mrn_rm`** line. **Local `rmstore_mrn` / FE hint do not raise cap above IMS.** **`totalqty`** only if no IMS/local line |
| **`remaining_qty`** | **`cap − coil_used − pending SA Add`** (unchanged). **Update / erp-search** pass **`exclude_adjustment_id`** so the row being edited is excluded from pending / approved SA coil credit |
| **`financial_year`** | Passed into budget on **create, update, approve, erp-search** so **`mrn_rm_old`** FY fallback matches Old gate load |
| **IMS** | **`fetchErpMrnOldByKey`**: full **`mrn_rm_old`**, then FY-filtered fetch if missing. **`mrn_rm`** via **`fetchErpMrnByKey`** keeps **30s cache** (portal / stickers unchanged) |

### Frontend (`StockAdjustmentDrawer`)

| Topic | Summary |
|-------|---------|
| **`editBaselineQty`** | Saved row **`qty` at load** only — ceiling must **not** follow live **`totalQty`** while typing |
| **`mrnQtyCeiling`** | **New Add:** API **`remaining_qty`**. **Edit:** **`remaining_qty`** when &gt; 0 (erp-search sends **`exclude_adjustment_id`**); if API still 0, allow re-save up to **`editBaselineQty`** only |
| **Over cap** | Total / coil sum clamped; toast *Maximum … KG for this MRN (internal receipt limit)* |
| **Save / update** | Validates against **`mrnQtyCeiling`**; backend **`assertAddQtyWithinMrnLimit`** is final |

### Behaviour

| Case | Before | After |
|------|--------|--------|
| UID only on **`mrn_rm`** | Cap = live line | **Same** (no **`mrn_rm_old`** row) |
| **`mrn_rm` + `mrn_rm_old`** (e.g. 1145 vs 2790) | False “fully used”, cap 1145 | Cap **2790** from old line; **`remaining_qty`** = 2790 − coils − other pending SA |
| **Edit pending row** (e.g. 1627 KG) | UI/API block or unlimited increase | Save within **remaining** (e.g. ≤ **1645**); **cannot exceed IMS cap** |
| **Increase qty on edit** | Could exceed MRN (ceiling tracked form total) | Capped at **`mrnQtyCeiling`**; increase only within API **remaining** |

erp-search / edit load expose **`it_recp_qty`**, **`remaining_qty`**, **`coil_used_qty`** from **`computeMrnQtyBudget`**, not raw IMS row only.

### Files (reference)

| Area | Path |
|------|------|
| Receipt cap + budget | `backend/src/apps/rmstore/modules/stock-adjustment/utils/mrnQtyBudget.js` |
| Update / create limit | `backend/src/apps/rmstore/modules/stock-adjustment/controllers/stockAdjustment.controller.js` |
| IMS old row lookup | `backend/src/apps/rmstore/modules/mrn/utils/resolveMrnForSticker.js` |
| ERP search enrich | `backend/src/apps/rmstore/modules/mrn/controllers/mrn.controller.js` |

## HRMS Daily Attendance audit tracking

### 26 Sep 2026

| Topic | Summary |
|-------|---------|
| **Daily Attendance — audit columns** | List shows Created / Updated / Approved **By** and **At** (same style as IMS Location Master) |
| **Create** | Sets `created_by` / `created_at` (existing table columns; already set on save) |
| **Edit** | Sets `updated_by` / `updated_at` only; clears approval so the row must be approved again |
| **Approve** | Sets `approved_by` / `approved_at` only; does **not** change updated fields |
| **Approve lock** | Already-approved rows: Approve disabled; toast asks user to Edit first, then Approve again |
| **API lock** | Re-approve without an edit returns **409** |
| **Helpers** | Uses shared `applyApprovalUpdateFields` / `normalizeApprovedInput` / `auditUserName` (Location Master pattern); maps `approved` → `approval_status` |

Same pattern as IMS **Location Master**. No change to punch / shift / entry-type business rules. Table already had audit columns — no schema change required.

---

### Behaviour

| Action | Audit fields | Approval |
|--------|--------------|----------|
| Create | `created_by`, `created_at` | Unapproved or auto-approved per existing save rules; approved rows also set `approved_by` / `approved_at` |
| Edit (business change) | `updated_by`, `updated_at` | Status → unapproved; `approved_by` / `approved_at` cleared (same as Location Master) |
| Approve | `approved_by`, `approved_at` | Status → approved; `updated_by` / `updated_at` unchanged |
| Approve again (no edit) | — | Blocked (UI + API 409) |

**UI flow after approval**

1. Approve → Approve button disabled.
2. Edit → save → row pending again; Approve enabled.
3. Approve again → `approved_by` / `approved_at` refreshed.

Toast when Approve is blocked:

`This record is already approved. Edit it before approving again.`

### Backend update path

`updateAttendance` builds a field bag, then:

1. `applyApprovalUpdateFields` (`auditAsName: true`, `alreadyApproved` from current `approval_status`)
2. Maps boolean `approved` → `approval_status` (`approved` / `unapproved`)
3. SQL sets `updated_*` only when the helper set them; sets `approved_*` only when the helper set them

| Case | Result |
|------|--------|
| Approve + already approved + no punch/shift change | **409** — edit required first |
| Approve without authorize permission | **403** |
