## v3.4.34 — Shared Location Master (IMS + rmstore)

IMS and rmstore now share a single location table (`ims_location_master`).  
Apps are isolated by `type`. IMS supports **multiple customers and items** per location.  
Legacy tables and single-value columns are migrated and cleaned up on startup.  
Existing inward, coil location, location finder, and QR flows remain compatible.

**Also in this release:** location **`rule`** (include/exclude), **RM multi items**, and **app-level** Location / Capacity validation toggles (see §4–5).

| | |
|--|--|
| **UI** | `/ims/` → Location Master · Inventory Inward · `/rmstore/` → Store Location · Store In · Settings → App Configuration |
| **DB** | Shared `ims_location_master` (+ `rule`) |
| **Config** | `inward_location_validation` · `location_capacity_validation` |
| **Scope** | Frontend + backend (schema, migration, APIs, forms, validation, App Config) |

---

### Problem (before)

| Issue | Detail |
|-------|--------|
| Dual masters | IMS used `ims_location_master`; rmstore used `coil_location` / `rmstore_master_location` |
| Sync risk | Same rack/shelf could diverge; coil FKs pointed at a separate table |
| Single binding | IMS locations stored only one `acc_code` and one `item_dcode` |
| Unclear type | Legacy codes such as `Y` / `R`; type was exposed or inconsistent in UI |
| Allowlist only | Customer/item lists always meant “only these allowed” — no exclude |
| No capacity gate | Store In could place more boxes/coils than `total_capacity` |
| RM single item | Store Location form allowed only one RM item |

---

### Solution (after)

```
┌─────────────────────────────────────────┐
│         ims_location_master             │
│  type = 'ims'  |  type = 'rmstore'      │
│  acc_codes[]   |  item_dcodes[]         │
│  rule = include | exclude               │
└────────────┬────────────────────────────┘
             │
     ┌───────┴────────┐
     ▼                ▼
  IMS Location      rmstore Store Location
  (boxes)           (coils.location_id)

inward_location_validation / location_capacity_validation (App Config)
        │
        ├─ Location validation ON  → IMS inward customer/item rules
        └─ Capacity validation ON  → IMS box capacity · RM coil capacity
```

### 1. Shared table and columns

**Table:** `ims_location_master`

| Column | Type | Purpose |
|--------|------|---------|
| `type` | `VARCHAR(50)` default `ims` | App key: `ims` \| `rmstore` |
| `acc_codes` | `INTEGER[]` default `{}` | Customers (multi) |
| `item_dcodes` | `INTEGER[]` default `{}` | Items (multi) |
| `rule` | `VARCHAR(20)` default `include` | `include` \| `exclude` (IMS) |
| `rack_no` / `shelf_no` / `location_no` | unchanged | Location identity |
| Capacity + audit fields | unchanged | Same as before |

**Removed after backfill:**

- Columns `acc_code`, `item_dcode` — values copied into arrays, then dropped
- Tables `coil_location`, `rmstore_master_location` — data migrated, then dropped (only after a successful migrate)

**Read aliases (backward compatible):**

```sql
(acc_codes)[1]   AS acc_code
(item_dcodes)[1] AS item_dcode
```

**Indexes (active rows), scoped by type:**

- Unique: `(rack_no, shelf_no, type)` — same rack/shelf allowed in both apps independently
- Unique: `(location_no, type)` when `location_no` is non-empty
- GIN on `acc_codes`, `item_dcodes`
- Pre-type unique indexes are dropped

Unique index creation fails soft on legacy duplicates so startup is not blocked; a warning is logged.

**File:** `backend/src/apps/ims/lib/config/tables/location/location_master.table.js`

### 2. App isolation (`type`)

| App | Forced `type` | UI |
|-----|---------------|-----|
| IMS | `ims` | Hidden (set on server) |
| rmstore | `rmstore` | Hidden (set on server) |

**Server rules:**

- List, get, views, create, update, and delete always enforce the app’s `type`
- Clients cannot override `type`
- Duplicate rack + shelf checks are within the same type only
- On boot, blank / `Y` / `IMS` → `ims`; `R` / `RM` → `rmstore`

**Constants:** `LOCATION_APP_TYPE_IMS` / `LOCATION_APP_TYPE_RMSTORE` in  
`backend/src/apps/ims/modules/location/models/locationMaster.model.js`

**rmstore naming:** DB column remains `shelf_no`; API/UI continue to use `row_no`  
(`lm.shelf_no AS row_no`).

### 3. Multi customer / item (IMS) + multi RM items

#### Save (IMS)

| Input | Stored |
|-------|--------|
| `acc_codes: [1, 2, 3]` | `acc_codes` array |
| `item_dcodes: [10, 20]` | `item_dcodes` array |
| Single `acc_code` / `item_dcode` (compat) | One-element array |

Empty arrays mean an open location (no customer/item restriction).

#### Save (rmstore)

- Store Location form/API accept **`item_dcodes[]`** (multi-select)
- Single `item_dcode` still accepted as fallback → one-element array

#### List / enrich

- Names resolved via IMS maps
- `acc_name` / `item_code` are comma-joined labels
- First id still available as `acc_code` / `item_dcode` aliases

#### Location suggestion (finder / inward)

| Tier | Match |
|------|--------|
| 1 | Box customer **in** `acc_codes` **and** item **in** `item_dcodes` (include-mode only) |
| 2 | Customer in `acc_codes`, location has **no** items (include-mode only) |
| 3 | Location has **no** customers, item in `item_dcodes` (include-mode only) |
| 4 | Open location (both arrays empty) |

#### Frontend

- IMS `LocationModal`: multi customer + multi item; **Rule** dropdown only when ≥1 item selected
- rmstore `LocationModal`: multi RM item select (`multiple` + `compactMulti`)

### 4. Location validation (app-level)

**Why:** Operators need customer/item rules without always turning on capacity.

**What**

| | |
|--|--|
| **Label** | Location validation (renamed from Inward location validation) |
| **Key** | `inward_location_validation` |
| **Default** | `false` |
| **Where** | App Configuration → IMS and RM Store (shared key) |

**How**

| App | When Enabled | When Disabled |
|-----|--------------|---------------|
| **IMS** | Enforce Location Master customer / item include-exclude on inward (create / update / scan / batch) | Skip rule checks |
| **RM Store** | Toggle is shown (shared). RM locations support **multi items only** (no multi customer). Store In does not enforce item rules yet | — |

**Column:** `rule` (`include` \| `exclude`, default `include`).  
Startup renames draft `restriction_mode` → `rule` if present.

| When | Behaviour |
|------|-----------|
| No items on location | Rule UI hidden; always **include** (customer allowlist if set) |
| ≥1 item selected | Rule dropdown shown |
| Location validation **Off** | No customer/item rule checks |

When Location validation is **On**:

| Rule | Lists set | Behaviour |
|------|-----------|-----------|
| `include` | Yes | Box must match listed customer(s) and/or item(s) |
| `exclude` | Yes (≥1 item) | Listed customer(s) / item(s) are **blocked** |
| — | Both empty | Open location (any box) |

**Files:**  
`ims/.../inwardLocationValidation.js` · `ims/lib/config/app.config.js` · `rmstore/lib/config/app.config.js`

### 5. Capacity validation (app-level)

**Why:** Capacity must be optional and independent of location rules.

**What**

| | |
|--|--|
| **Label** | Capacity validation |
| **Key** | `location_capacity_validation` (**new**) |
| **Default** | `false` |
| **Where** | App Configuration → IMS and RM Store (shared key) |

**How**

| Setting | Behaviour |
|---------|-----------|
| **Enabled** | Projected stock cannot exceed `total_capacity` |
| **Disabled** | Any quantity allowed |
| `total_capacity` null / 0 | Capacity check skipped (open) |

#### List / display occupancy (unchanged)

Occupied = in-hand **boxes** on the location + active/rejected **coils** on the location.  
Available = `max(total_capacity − occupied, 0)`.

#### Store In enforcement

When Capacity validation is **On** and `total_capacity > 0`:

| App | Count | Rule |
|-----|-------|------|
| IMS | Boxes only (in hand) | occupied + new ≤ `total_capacity` |
| RM Store | Coils only (active/rejected) | occupied + new ≤ `total_capacity` |

Items already on that location are not double-counted. IMS loads `type=ims` only; RM loads `type=rmstore` only.

**Behaviour matrix**

| Location validation | Capacity validation | Result |
|---------------------|---------------------|--------|
| Off | Off | No rule / capacity checks |
| On | Off | Rules only (IMS) |
| Off | On | Capacity only |
| On | On | Rules + capacity |

**Upgrade:** Sites that used `inward_location_validation = true` for capacity must also set **`location_capacity_validation = true`**.

**Files:**  
`appConfig.model.js` (`isLocationCapacityValidationEnabled`) · IMS + RM `inwardLocationValidation.js` · App Config FE layouts · login/me session payload

### 7. Compatibility — must not break

| Flow | Why it remains safe |
|------|---------------------|
| Packing / inventory inward location pick | Views use aliases; IMS filters `type=ims` |
| Location finder | Hierarchy matches any value in arrays (include tiers) |
| Location QR (IMS + rmstore) | Uses `location_no` / rack+shelf; rmstore keeps `row_no` alias |
| Coil assign / reports / out-entry | Join on `location_id` → shared master |
| rmstore location CRUD | API still uses `row_no`; maps to `shelf_no` |
| Out / SA / packing / helpers | No new validation; display/join only |
