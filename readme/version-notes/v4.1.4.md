## What changed

### Pending → Show

| Option | API | Client extra |
|--------|-----|----------------|
| All Open | `open_only: true` | Incomplete holds |
| Awaiting Approval | `open_only: true` | `has_pending_submission` |

Show → **Complete** does **not** open From / To. Dates stay on **Transaction Log** only.

`date_on: activity` still uses `COALESCE(updated_at, created_at)` for `can_view_days`, so a recently finished older hold still appears. No `from_date` / `to_date` is sent.

- If no boxes left (legacy stuck holds) → allow approve (`noSourceBoxes`).

# H. Forwarding Note — max dispatchable qty beyond schedule balance

|           |                                                                 |
|-----------|-----------------------------------------------------------------|
| **UI**    | IMS → Forwarding Note (Schedule flow / Item Breakdown modal)    |
| **Config**| IMS App Configuration key: `forwarding_shortage_qty_percentage` |
| **API**   | Schedule picker + Forwarding save validation (existing routes)   |
| **DB**    | No schema change (uses existing `ims_app_config`)               |
| **Dates** | 10 Sep 2026                                                      |

## What changed

- Added IMS AppConfig key `forwarding_shortage_qty_percentage` (0–100, default **0**). Separate from packing `shortage_qty_percentage`.
- Schedule rows carry `shortage_qty_percentage` from config (schedule planning attach).
- Formula (when `% > 0`):
  - `max_extra = floor(balance × pct / 100)`
  - `max_allowed = balance + max_extra`
  - UI typed cap = `min(FG stock, max_allowed)`
  - Example: balance 1000, 10% → max **1100**
- Auto FIFO still **targets balance**; always **full boxes** (`calculateFifoBoxes` — never split a box).
- No extra UI fields; silent rule.

## `% = 0` vs `% > 0`

| Config | Behaviour |
|--------|-----------|
| **`0` / unset** | **Old FIFO** — target = balance; last full box may overshoot (e.g. 1000 → 1200). No FE “max allowed” toast for that overshoot. BE **skips** max-allowed reject. |
| **`> 0`** | Typed qty capped at `max_allowed`. Toast: `Cannot exceed maximum allowed quantity`. BE save rejects demand above `max_allowed`. |

## Validation and safety

- FE (`ForwardingModal`): over-max toast only when item/config `% > 0` (deferred `setTimeout` so ToastContainer does not warn setState-in-render).
- BE (`assertScheduleDispatchWithinBalance`): max-allowed check **only if** `forwarding_shortage_qty_percentage > 0`. Schedule existence check always runs.
- Edit save uses `exclude_fuid` so the note’s own qty is not double-counted in balance.

## Files touched

| File | Change |
|------|--------|
| `frontend/.../forwarding-note/ForwardingModal.js` | Cap helpers; toast only when `% > 0`; full-box FIFO |
| `backend/.../schedule-planning/.../schedulePlanService.js` | Attach `shortage_qty_percentage` on schedule rows |
| `backend/.../forwarding-note/.../forwardingNoteItemsWrite.js` | Save max-allowed **only when % > 0** |
| `backend/.../configuration/models/appConfig.model.js` | `getForwardingShortageQtyPercentage()` |
| `backend/.../ims/lib/config/app.config.js` | Key + seed + label |
