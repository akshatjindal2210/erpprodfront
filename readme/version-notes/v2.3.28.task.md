## Task App — version notes *(17 Jul 2026)*

Summary of Task module UI / flow updates (Tasks list, Report, Recurring Tasks, assignment rules, Super Admin complete, Admin user CL verifier). Working API/business logic kept the same unless noted.

---

### Tasks list — IMS DataTable + color codes

**Problem:**
- Tasks list chrome was partially IMS-aligned, but the table was still a custom HTML grid (not shared `DataTable`).
- Sticky columns leaked scrolled text; Actions was not fixed on the right.

**Cause:**
- Custom `<table>` + `TaskTableRow` instead of IMS `DataTable`.
- Row tint used translucent hex (`#rrggbb18`), so sticky cells showed content underneath.

**Fix:**
- Tasks page uses IMS `DataTable` with the same Task color palette (`getTaskDataTableRowClassName` — opaque tints).
- Left sticky: selection + `#` (task id); right sticky: **Actions**.
- Toolbar: View / Edit / Clone / Delete on single-row select (IMS pattern); Self Task / Assign Task / Refresh / fullscreen kept.
- Card (“stack”) view unchanged: `TaskCard` grid + color bar.
- Stat cards, filters, session persistence, fetch/sort/load-more logic unchanged.

**Flow:**
1. Task → Tasks → table or card toggle
2. Filters / stat cards filter the same loaded set as before
3. Select row → View / Edit / Clone / Delete (owner rules same)
4. Double-click / View → task detail (complete / approve still on detail)

**Reflects:**
- Tasks list table chrome, sticky columns, row colors, toolbar actions

**Files:**
- `frontend/src/features/apps/task/components/tasks/Page.js`
- `frontend/src/features/apps/task/components/tasks/taskListTableHeaders.js`
- `frontend/src/features/apps/task/components/tasks_common_component/TaskHelper.js` — opaque DataTable row classes
- `frontend/src/core/components/ui/DataTable.js` — `fixed` / `fixedRight` sticky helpers

### Tasks + Report — export matches table (PDF / Excel / CSV)

**Problem:**
- Export used raw field keys (`category_id`, `last_remark`, `assigned_by`, …), so files did not match what the table shows.

**Cause:**
- `TABLE_COLS.map(label, key)` without display formatters / `copyValue`.

**Fix:**
- Shared `buildTaskExportHeaders()` exports the same visible values as the table:
  - Task ID, Title, Last Remark, Status, Due / Reminder dates, Category name, Priority label, Assigned By / To, Created At, Type, Created By
- Wired on **Tasks** and **Report** pages.
- Actions column excluded from export.

**Flow:**
1. Apply filters → export PDF / Excel / CSV
2. File columns/values match the filtered table view

**Reflects:**
- Tasks + Report export toggle

**Files:**
- `frontend/src/features/apps/task/components/tasks/taskListTableHeaders.js` — `buildTaskExportHeaders`
- `frontend/src/features/apps/task/components/tasks/Page.js`
- `frontend/src/features/apps/task/components/reports/ReportPage.js`

### Recurring Tasks — IMS list + card stack + stat filters

**Problem:**
- Recurring card view used generic DataTable cards (not Task-style stack).
- Total / Active / Inactive / Created Today were a thin text strip, not colored stat cards.
- Status / Member filter boxes were white “server” style while Quick Search was indigo (client filter).

**Cause:**
- `RecurringTaskCard` existed but was not wired; page always passed `viewMode` into `DataTable`.
- Filters are client-side after full load; they still used `variant: "server"` styling.

**Fix:**
- Table mode: IMS `DataTable`; card mode: `RecurringTaskCard` grid (top color bar + tint).
- Card / legend colors = frontend filter buckets only:
  - Total `#696969` · Active `#2bff00` · Inactive `#ff8800` · Created Today `#0011ff`
- Stat cards clickable → client filter (Active / Inactive / Created Today); full list still loaded once (stable counts).
- Status + Member filters use `variant: "quick"` (same indigo look as Quick Search).
- Edit / Delete / Active toggle / search / member filter logic unchanged.

**Flow:**
1. Task → Recurring Tasks → table or card
2. Click Total / Active / Inactive / Created Today → list filters on frontend
3. Status / Member dropdowns same indigo client-filter look as Quick Search
4. Select → Edit / Delete; Active toggle on row/card

**Reflects:**
- Recurring list, card stack, stat strip, filter bar colors

**Files:**
- `frontend/src/features/apps/task/components/recurring-task/Page.js`
- `frontend/src/features/apps/task/components/recurring-task/RecurringTaskCard.js`
- `frontend/src/core/components/common/SearchableSelect.js` — `filterVariant` (`quick` | `server`)
- `frontend/src/core/components/common/DateRangeFilter.js` — passes `filter.variant` to searchable extras
- `backend/src/apps/task/models/recurringTask.model.js` — `getStats` ignores list `is_active` so overview cards stay stable
- `backend/src/apps/task/controllers/recurringTask.controller.js` — stats call without active filter

### Assign By / Assign To rules

**Problem:**
- Assign By and Assign To could be the same person; Assign By still appeared in Assign To list.

**Fix (UI + backend):**
- Creator may be Assign To.
- Assign By ≠ Assign To (validation).
- Assign By user excluded from Assign To options; changing Assign By clears Assign To if they match.
- Same rules on create/update API.

**Reflects:**
- Task / Recurring task modals; create/update task API

**Files:**
- `frontend/src/features/apps/task/components/tasks/TaskModal.js`
- `frontend/src/features/apps/task/components/tasks/RecurringTaskModal.js`
- `backend/src/apps/task/controllers/task.controller.js`

### Super Admin — complete any user task

**Problem:**
- Super Admin needed to complete others’ tasks; when SA is also L1, force-complete should not skip creator approval.

**Fix:**
- UI: Admin Complete when SA and not in approval states; Final Approve/Reject on `creator_pending`; L1 Approve/Reject on `pending_approval`.
- Backend `requestCompletion`:
  - SA **and not** active L1 → force complete
  - SA **is** active L1 → normal L1 → `creator_pending`
  - Sub-user / L1 paths unchanged for non-SA

**Reflects:**
- Task detail action buttons + complete API

**Files:**
- `frontend/src/features/apps/task/components/tasks/SubPage.js`
- `backend/src/apps/task/controllers/task.controller.js` — `requestCompletion`
