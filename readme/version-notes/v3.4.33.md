## v3.4.33 — IMS Stock Adjustment: **Update** (box qty) *(21 Aug 2026)*

Adds a third Stock Adjustment type **Update** next to **Add (+)** and **Minus (−)**.  
One existing in-hand box is scanned; qty is planned on Save and applied only on **Approve**.  
Add / Minus / legacy adjustment flows are unchanged.

| | |
|--|--|
| **UI** | `/ims/` → Stock Adjustment |
| **API** | existing `POST /api/ims/stock-adjustment/…` + `POST /api/ims/boxes/helper` |
| **Entry type** | `entry_type: "update"` |

---

### What Update is (and is not)

| | Update | Add | Minus |
|--|--------|-----|-------|
| Input | Scan **one** box sticker (`box_no_uid`) | Packing no. + FY | Packing no. → tick boxes |
| Inventory on Save | **No change** (pending plan) | No boxes until Approve | No remove until Approve |
| Inventory on Approve | Live box `qty` ± entered qty | Create boxes | Mark boxes stock_out |
| Stickers | Reprint that box after Approve | Print new SA boxes | No print |

---

### End-to-end workflow

```
NEW → Type = Update
  → Scan / type box sticker (QR / laser / keyboard) → Load
  → Box must be IN HAND
  → UI: current qty (read-only) + Action Add(+) / Minus(−) + qty
  → Preview: New qty after approve + Net PCS
  → Save  → Pending adjustment (box qty UNCHANGED)
  → Approve → Box qty applied (or reject if qty drifted / not in hand)
  → Print stickers (approved Update only) → that one box
```

Edit of an **approved** Update: Save resets to Pending, **reverts** the previous applied delta (box must still be in hand), then stores the new plan. Approve again to re-apply.

---

### Scan: which box appears

1. Sticker parsed with shared IMS helpers (`parseStickerScan` / `extractBoxCode`).
2. Lookup via `boxes/helper` with `permission_module: "stock_adjustment"`, `permission_action: "view"`.
3. Match: exact / case-insensitive `box_no_uid`, numeric `box_uid`, or underscore-suffix (e.g. typed `30818_5_1` vs stored `2026_30818_5_1`), plus soft list-search fallback on FE.
4. **In hand only** — dispatched / stock_out / SA-removed boxes are rejected at scan and at create.
5. UI shows **that single box** in the breakdown table (same columns as Minus: #, Box, Packing, Customer, Qty, Type, Status).
6. Left detail cards load packing context when `packing_number` exists (item / customer / production). Breakdown Summary shows **Current Qty**, **Add (+)**, **Minus (−)**, **After**.

### Add (+) / Minus (−) on Update (qty change)

| User action | Validation | Stored plan (`removed_box_ids` JSON) | On Approve |
|-------------|------------|--------------------------------------|------------|
| **Add (+)** qty `N` | `N ≥ 1` | `{ kind: "qty_update", update_action: "add", update_qty: N, snapshot_qty, box_uid, … }` | `live + N` |
| **Minus (−)** qty `N` | `N ≥ 1` and `current − N ≥ 0` | same with `update_action: "minus"` | `live − N` (never &lt; 0) |

- Top fields: **Current qty**, **New qty (preview)**, breakdown **Qty impact** = `+N` / `−N` / `—` if empty.  
- Impact is the **typed** qty, not the full box qty (full box qty stays in the table row).  
- Adjustment row `qty` = signed delta (`+N` / `−N`); `box_count_impact` = `1`; `per_box_qty` = snapshot at save.

---

### In stock vs not in stock

| State | Scan / Create | Approve | Edit approved / Delete (revert) |
|-------|---------------|---------|----------------------------------|
| **In hand** | Allowed | Allowed if live qty still equals `snapshot_qty` | Revert delta, then new plan / delete |
| **Not in hand** (dispatched, stock_out, etc.) | Blocked | Blocked | Blocked — cannot rewrite qty on an outward box |
| **Qty changed after Save** (another movement) | — | Blocked: edit & save again before approve | — |

Pending Update never changes inventory until Approve. Unapprove / delete of an applied Update undoes the delta only if the box is still in hand.

---

### Print stickers

- Enabled for **approved Add** and **approved Update** only.  
- Update prints the **single** scanned box (updated qty).  
- Minus remains non-printable (unchanged).

---

### Safety vs Add / Minus

- All Update paths are gated by `entry_type === "update"`.  
- Minus plan JSON (`uids` / customer lines) and Update plan (`kind: "qty_update"`) do not overlap.  
- Shared drawer / helper / packing-meta paths keep existing Add / Minus branches.  
- Box sticker lookup improvements (trim / suffix) are shared but only make existing scans more tolerant.

### Operator checklist

1. New → **Update** → scan an **in-hand** sticker → Load.  
2. Choose **Add (+)** or **Minus (−)** → enter qty → confirm preview / Net.  
3. **Save** (Pending) — verify box qty in Boxes / Finder is unchanged.  
4. **Approve** — box qty updates; list shows signed Total qty.  
5. **Print stickers** on that authorized Update row.  
6. Confirm Add / Minus still work on packing numbers as before.
