### Auto Deviation — New Sticker

Manual **Create Deviation** still uses shortage balance. **Auto Deviation** is separate and does not gate on shortage.

On New Sticker, Auto runs from `autoPackingDeviation` in `shortage.controller.js`:

```
check  = FG + current packing − schedule balance
excess = shortage shortfall (projected − allowed), ceil

Auto creates Deviation(excess) when:
  excess ≥ 1
  AND (item Max ≤ 0 OR check ≤ item Max)

Otherwise Auto skips (sticker may still open if packing is otherwise within limit).
```

| Piece | Role |
|-------|------|
| Schedule balance | Used only in the Auto **gate** (`check`) |
| Shortage / excess | Used only for Auto **qty** (and for manual Create Deviation) |
| Item Max | Cap on `check`; Max `0` / empty turns the Max gate off |
| FG | Sellable in-hand stock (not the same as month stickered qty) |

After create, packing limit is re-checked; if still over limit the Auto row is reverted.

### RM Stock Adjustment — scan to approve

Stock Adjustment approve matches MRN Portal:

1. Stickers are generated while the entry is still pending.
2. Approver (authorize permission) opens **Approve**.
3. Each required coil sticker is scanned.
4. Submit → entry becomes approved.

Print is blocked during approve on Stock Adjustment and MRN Portal (no QC sticker / Print All on the approve screen). On phone, the Sticker tab opens by default in approve mode.

Pending adjustments can still print stickers so coils exist for the scan step.

### HRMS — Attendance Log (sort · search · copy · print)

**Attendance Log** uses `ServerListPage` with **Quick Search** (client-side filter on loaded rows). Three gaps were fixed to match IMS list behaviour.

| Issue | Cause | Fix |
|-------|--------|-----|
| ASC / DESC did nothing | `DataTable` sort was not wired in `ServerListPage` | `sortKey` / `sortDir` + `sortRowsByKey` on filtered rows |
| Quick Search missed visible text | Search used raw row fields (e.g. ISO timestamps), not formatted display | `buildTableSearchParts()` searches the same text as copy/export |
| Copy / Excel / PDF wrong values | JSX cell renderers had no `copyValue` | `copyValue` on every column in `attendanceLogColumns.js` |

**Default sort:** `event_timestamp` descending (newest event first).

**Date columns** sort on `event_timestamp` / `created_at` but display `event_datetime_display` / `created_at_display`.

**WYSIWYG rule:** whatever appears in the table is what Quick Search matches, Ctrl+C copies, and export/print includes (filtered set, not just the visible scroll slice).

Shared helpers (also used by other server lists with fixed headers):

| File | Change |
|------|--------|
| `ServerListPage.js` | Sort toggle; Quick Search via `buildTableSearchParts` when headers define `copyValue` |
| `clientListSearch.js` | `buildTableSearchParts()`; `event_timestamp` treated as date sort key |
| `attendanceLogColumns.js` | Per-column `copyValue`; clean formatting |

**HRMS Activity Logs** (`AppActivityLogPage`): sort UI existed but rows were never re-ordered after fetch. Loaded rows are now sorted client-side with `sortRowsByKey` before display/export.
