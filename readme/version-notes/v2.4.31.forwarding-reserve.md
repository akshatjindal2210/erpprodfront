## v2.4.31 — Forwarding Note Reservation vs Out Entry *(1 Aug 2026)*

---

### Forwarding Note — duplicate packing allocation across notes

**Problem:**
- Stock was reserved on Forwarding Note **811**, yet the same packing numbers (e.g. **35771**, **36361**, **37564**) appeared on Forwarding Note **812**.
- This appeared to be a FIFO violation or a failure of the reservation system.

**Root cause:**
- Forwarding Note reservations were released when the linked Out Entry reached **`scan_complete`**.
- Physical stock remains sellable until the Out Entry is **`approved`**, at which point `out_uid` is set on `ims_box_table` and boxes leave inventory.
- Between scan completion and approval, a second Forwarding Note could reserve the same boxes because the first note was no longer counted as reserved.

**Observed timeline (FN 811 / FN 812):**

| Time      | Event |
|-----------|--------|
| 14:32     | FN 811 saved and approved — stock reserved |
| 14:52     | FN 812 header created (line items saved later) |
| 15:00     | FN 811 Out Entry scan complete — reservation **released** (previous behaviour) |
| 15:00:23  | FN 812 line items saved — FN 811 not treated as reserved; same packings allowed |
| 16:07     | FN 811 Out Entry approved — stock physically dispatched |

**Fix:**
- A Forwarding Note reservation now remains active until its linked Out Entry is **approved**.
- **`scan_complete` alone no longer releases the reservation** — release is aligned with physical stock leaving inventory.

**Files changed:**

| File | Change |
|------|--------|
| `backend/src/apps/ims/modules/forwarding-note/models/forwardingNote.model.js` | In `findForwardedQtyByItemAndPacking` and `findAllForwardedReservesByItemAndPacking`, Out Entry exclusion criteria changed from `scan_complete` to `approved` |

**Frontend:** No code changes — the fix is limited to the backend reservation queries.

**Note:** The same packing number may legitimately appear on two Forwarding Notes when sufficient physical quantity remains on that packing (partial allocation by design). The defect occurred when quantity that should still have been locked on the first note became available to the second.
