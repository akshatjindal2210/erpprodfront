## v3.4.36 — Gate Entry Edit, Shortage Bulk Import, Month TZ Fix & Permission Cache

This release adds **Gate Entry meta edit** (transporter / vehicle / remarks), **Shortage Super Admin PPC bulk import** (preview + submit), **Shortage month** for Super Admin on New/Edit/Approve, fixes **month showing one month early** (DATE timezone), and clears the **permission cache** so newly granted IMS/Shortage access works without a stuck “no access” state.

|           |                                                                                         |
|-----------|-----------------------------------------------------------------------------------------|
| **UI**    | Gate Entry Complete (View/Edit) · Shortage list Import · Shortage modal month           |
| **API**   | `POST /shortage/bulk-preview` · `POST /shortage/bulk` (Super Admin) · gate update (existing) |
| **DB**    | No new migration — PG DATE parser returns `YYYY-MM-DD` string globally                  |
| **Scope** | IMS · Gate Entry · Shortage · Core permissions cache                                    |
| **Dates** | **31 Aug 2026**                                                                         |

| Issue | Detail |
|-------|--------|

- Uses existing `POST /gate-entries/update` + `updateGateEntryMeta`.

## Part B — Shortage: Super Admin bulk PPC import

### Problem (before)

| Issue | Detail |
|-------|--------|
| No bulk path | Large PPC shortage lists had to be entered one-by-one |
| Duplicate risk | Same item could be entered twice for the same calendar month via import |

### Solution (after)

```
  Month + CSV/Excel
        │
        ▼
  Client parse (A=item_dcode, B=item_code, C=qty)
        │
        ▼
  POST /shortage/bulk-preview  ──► Item · Desc · Qty
        │                         (grey = skip / invalid)
        ▼
  Submit → POST /shortage/bulk
        │
        ├─ type always PPC (auto-approved)
        ├─ group same item (sum qty)
        ├─ skip if not in IMS
        └─ skip if PPC already exists for same item + calendar month
```

| Rule | Behaviour |
|------|-----------|
| Who | **Super Admin only** (UI button + `authorize("super_admin")`) |
| Type | Always **PPC** |
| UI | Month · CSV/Excel · preview table · footer **total · save · skip** · Submit |
| Normal CRUD | New / Edit / Approve **unchanged** (import-only duplicate skip) |

### Files

| File | What changed |
|------|----------------|
| `backend/.../shortage/controllers/shortage.controller.js` | `previewBulkShortages` · `bulkCreateShortages` · group/IMS/skip helpers |
| `backend/.../shortage/routes/shortage.route.js` | `/bulk-preview` · `/bulk` |
| `frontend/.../shortage/ShortageBulkImport.js` | Import drawer UI |
| `frontend/.../shortage/parseShortageImport.js` | Header or headerless column parse |
| `frontend/.../shortage/Page.js` | Import button if Super Admin |
| `frontend/.../lib/services/shortage.js` | `bulkPreview` / `bulkCreate` |
| `frontend/.../lib/config/endpoints.js` | `BULK` · `BULK_PREVIEW` |

## Part C — Shortage modal: month for Super Admin

### Problem (before)

| Issue | Detail |
|-------|--------|
| No month control | Super Admin could not set calendar month on create/edit/approve in the form |
| Wrong month display | Picking October sometimes showed / saved as September (JS `Date` + PG DATE timezone) |

### Solution (after)

- Super Admin sees **Month** (`YYYY-MM`) on New / Edit / Approve; Qty + Month half-half on one row.
- Form keeps month as pure `YYYY-MM`; save sends `YYYY-MM-01` (no Date round-trip).
- Non–Super Admin: create still uses today; no month field.
- **Global fix:** PG **DATE** (`oid 1082`) returned as `'YYYY-MM-DD'` string (not JS `Date`). TIMESTAMP / TIMESTAMPTZ unchanged.

### Files

| File | What changed |
|------|----------------|
| `frontend/.../shortage/ShortageModal.js` | Month field + `monthToSaveDate` |
| `backend/src/config/db/db.js` | `types.setTypeParser(1082, …)` |
