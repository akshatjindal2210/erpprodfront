## v2.2.30 — Forwarding Note: one item once per note *(18 Jul 2026)*

---

### Forwarding Note — Unique item (same item not twice on one FN)

**Problem:**  
On Today’s Dispatch Plan → **New** (no row) → customer → item dropdown, if **two schedules shared the same item** (e.g. SCH 25241 + SCH 25253, both HN005), both rows could be added to a single Forwarding Note. That allowed two FIFO picks for the same item (overlapping boxes / confusing qty). Stock was still managed via qty freeze, but the UI was confusing.

**Simple rule (fix):**  
**Each Forwarding Note may include a given `item_dcode` only once** — even if another Sch No has the same item.

**Frontend:**
1. Item dropdown: hide any schedule line for an item that is already on a row.
2. Retrying the same selection → toast: *This item is already on this note…*
3. Row select → **New** (prefill): same customer’s lines, **first line per item** (prefer the selected row).
4. Remaining balance from another schedule → **a separate Forwarding Note**.

**Backend (secure):**  
On create / update item save, validate the payload:
- Same `item_dcode` twice → **400** (blocks API bypass)
- Same `box_no_uid` on two item rows → **400** (blocks FIFO overlap)  
Note: after save, separate packing rows for the same item in the DB are normal — uniqueness applies only to modal/payload lines.

**FIFO:**  
No break. One item = one row = one FIFO pick. Double-claim risk removed.

**Process note (not a bug):**  
Two open schedules for the same item → two Forwarding Notes. Merging onto one note is not supported.

**Test:**
1. UI: New (no row) → HN005 SCH A add → SCH B / HN005 hide; toast on force.
2. API: create/update with two items same `item_dcode` → 400.
3. API: two items sharing same `box_no_uid` → 400.
4. Normal multi-item FN (different items) + multi-packing same item after save → OK.

- `frontend/.../forwarding-note/ForwardingModal.js` — duplicate item block + dropdown filter
- `frontend/.../forwarding-note/ForwardingPage.js` — dispatch-plan prefill dedupe
- `backend/.../forwarding-note/forwardingNoteItemsWrite.js` — `assertUniqueForwardingItemDcodes` + `assertNoDuplicateSelectedBoxes` on persist
