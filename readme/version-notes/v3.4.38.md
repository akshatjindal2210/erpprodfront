## v3.4.38 — CL Task Report, Verification, Include Sunday, Holiday Import, Tasks UX & IMS Box Dispatch Fix

## Part B — CL Task Report: scheduled days only (Weekly / Monthly / Yearly)

### Problem (before)

| Issue | Detail |
|-------|--------|
| Whole week coloured | Frequently task with **one weekday** (e.g. Monday) showed pending/missed on **every** day between start and today |
| Wrong period average | Non-scheduled days could drag down person period % |

### Solution (after)

```
  For each calendar column (ymd)
        │
        ▼
  shouldShowTaskDayCell(task, ymd)?
        │
        ├─ Has day_scores / day_states  → show
        ├─ Open task                    → only if stored fill day
        └─ Frequently                   → isClOccurrenceDay(recurrence, ymd)
              │
              ├─ daily   → every day (Sunday rules below)
              ├─ weekly  → selected weekday(s) only
              ├─ monthly → selected date(s) only
              └─ yearly  → selected MM-DD only
        │
        ▼
  Else → blank cell (none)
```

Report API now sends `recurrence_weekdays`, `recurrence_month_dates`, `recurrence_year_dates` on aggregated task rows.

Period / day-header scores count **only scheduled days** (plus days with stored instance data). Sundays are excluded from period average when all Frequently tasks have **Include Sunday** off.

### Files

| File | What changed |
|------|----------------|
| `frontend/.../lib/helpers/clTaskRecurrenceHelper.js` | **New** — client mirror of backend recurrence checks |
| `frontend/.../cl-task/report/ReportBookingCalendar.js` | Uses `shouldShowTaskDayCell`; removed whole-range pending fallback |
| `backend/.../reports/helpers/reportScore.helper.js` | `userHasScheduledDay`, `isFrequentTaskOccurrenceDay`, Sunday skip in `compileUserPeriodScores` |
| `backend/.../reports/controllers/reportPanel.controller.js` | Recurrence fields on frequent aggregated groups |

## Part C — Include Sunday (Frequently tasks only)

### Problem (before)

| Issue | Detail |
|-------|--------|
| Sunday always counted | Daily / weekly Frequently tasks spawned and scored on Sunday with no opt-out |
| Open tasks | Should not depend on this setting |

### Solution (after)

| Setting | Default | Applies to |
|---------|---------|------------|
| **Include Sunday** | **OFF** | **Frequently** schedule section only |

| Include Sunday | Spawn | Report grid | Period % |
|------------------|-------|-------------|----------|
| **OFF** | Skip Sunday | Sunday blank for Frequently | Sunday excluded from average |
| **ON** | Sunday allowed | Shows when task is due that day* | Sunday included when scheduled |

\*Weekly with only Monday selected still shows **Monday only** — Include Sunday does not add extra weekdays.

**Open tasks** are unchanged: if filled on Sunday, that day appears regardless of this flag.

## Part F — CL Task Report scoring (reference)

How scores compile after this release:

| Level | Formula |
|-------|---------|
| Task cell | Verifier rating 1–10 → `(rating ÷ 10) × 100%`; missed = 0%; no-verify completed = 100% |
| Person day % | `Σ(task % × weightage) ÷ Σ(weightage)` for tasks active that day |
| Person period % | Average of person day % over **scheduled days** in From–To (Sunday skipped when Include Sunday off on all Frequently tasks) |
| Day header % | Average of all users’ person day % that column |
| Score % card | Average of all persons’ period % |
| MIS / Red | `final_score_pct = clamp(weighted_score_pct + mis_score_total, 0…100)` |

Super Admin: **Score Formula** panel shows per-day breakdown expressions from the API.

## Part H — Not Viewed: exclude completed / closed

### Problem (before)

| Issue | Detail |
|-------|--------|
| Completed in Not Viewed | Tasks with status **completed** or **closed** still appeared when **Not Viewed** had unseen activity log entries |
| Misleading count | Stat card and list included finished work the user no longer needs to open |

### Solution (after)

**Not Viewed** now requires **both**:

1. Unseen updates (`taskUnseenUpdatesSql` — activity after last `task_viewed`)
2. Task status **not** `completed` or `closed`

Applies to list filter, count query, and dashboard **updated_tasks** stat.

Row highlight / **Not Viewed** badge on other tabs also skips completed and closed tasks.

### Files

| File | What changed |

## Part H — IMS Boxes: SA-add + colliding `out_uid`/`sa_id` shown as 13C

Full write-up: [v3.4.38.box-dispatch-sa-id.md](./v3.4.38.box-dispatch-sa-id.md)

### Problem (before)

A box created by stock-adjustment **add** (`sa_entry_type = stock_in`, sticker `…_SA366_…`) later dispatched on out entry **366**. Classification treated `out_uid === sa_id` as **minus**, so the list showed leftover location **13C** and Box Finder said **Box is here**. A sibling box on the **same** `OUT-366` (`sa_id` 367) correctly showed **DISPATCH**.

Example: `26_20669_SA366_1_1` (wrong 13C) vs `26_4890_SA367_1_1` (correct DISPATCH). Both journeys: `OUT — DISPATCHED`.

### Solution (after)

`stock_in` is never classified as minus. `out_uid === sa_id` is only a legacy minus marker when the box is **not** an SA add. Frontend zone classifies dispatch / in-hand before trusting API `stock_zone`.

### Files

| File | What changed |
|------|----------------|
| `backend/.../box/utils/inventory/boxInventory.js` | `isBoxStockAdjustmentOut` skips `stock_in` |
| `frontend/.../lib/utils/boxInventory.js` | Same rule |
| `backend/.../box/utils/inventory/boxInventorySql.js` | SA-minus SQL skips `out_uid = sa_id` when `stock_in` |
| `frontend/.../modules/box/boxTableVisuals.js` | `getBoxStockZone` live classify first |
