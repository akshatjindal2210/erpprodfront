# Dashboard Builder URL Data Source

## Purpose

This document explains the changes made to Admin Console → Dashboard Builder → Widget Builder for:

- The new `URL` data source.
- GET and POST API requests.
- JSON column selection.
- Dynamic Table search result counts.
- Validation, error handling, persistence, and security.

The implementation is additive. Existing PostgreSQL, SQL Server (ERP), SQL Server (HRMS), and Hybrid execution paths remain separate and unchanged.

## User Flow

1. Open Admin Console → Dashboard Builder.
2. Add or edit a KPI, Table, or Graph widget.
3. Select `URL` from the Database dropdown.
4. Select `GET` or `POST`.
5. Enter an HTTP or HTTPS API URL.
6. For POST, optionally enter a valid JSON request body.
7. Click Preview.
8. After JSON is returned, use Displayed Columns to uncheck keys that should be hidden.
9. Continue using the normal Preview, Save Draft, Publish, Delete Widget, page access, click-link, layout, and style options.

## Supported JSON

The API must return valid JSON.

An array of objects is used as widget rows:

```json
[
  {
    "name": "Item A",
    "quantity": 10
  },
  {
    "name": "Item B",
    "quantity": 20
  }
]
```

Common API envelopes are unpacked automatically so the table shows real data rows, not wrapper keys. These shapes are supported:

```json
{
  "success": true,
  "records": [
    { "itemcode": "2", "total_sales_qty": "6530" }
  ],
  "message": "OK"
}
```

```json
{
  "data": [
    { "id": 1, "name": "A" }
  ]
}
```

```json
{
  "data": {
    "records": [
      { "id": 1, "name": "A" }
    ]
  }
}
```

Recognized array keys (including nested one level under `data`): `records`, `data`, `rows`, `items`, `results`, `result`, `list`, `values`.

A plain object with no array payload is converted into one widget row:

```json
{
  "total": 125
}
```

Top-level strings, numbers, booleans, and `null` are rejected because the existing widget renderers require object-based rows.

## GET and POST Logic

GET requests:

- Send an `Accept: application/json` header.
- Do not send a request body.

POST requests:

- Send an `Accept: application/json` header.
- Send `Content-Type: application/json` when a body is provided.
- Validate and normalize the JSON body before sending it.
- Allow an empty body when the endpoint does not require one.

Only GET and POST are supported.

## Column Selection Logic

After Preview, the builder finds the union of keys across all returned object rows. This is important when later rows contain fields that are not present in the first row.

All discovered keys are selected by default. When a key is unchecked:

- Its name is stored in `chart_config.url_excluded_columns`.
- It is removed immediately from builder rendering.
- It is removed from live runtime data.
- Table display, search, sorting, and export use the remaining keys.
- Graph column selection uses the remaining keys.
- KPI widgets use the remaining data fields.

The builder keeps the unfiltered preview response available for the column checklist. This allows an excluded key to remain visible as an unchecked option and be selected again later.

## Persistence

The URL itself is stored in the widget's existing `query` field. The selected data source tells the backend whether this value is SQL or an API URL.

The following URL settings are stored in `chart_config`:

```json
{
  "data_source": "url_json",
  "url_method": "POST",
  "url_body": "{\"status\":\"active\"}",
  "url_excluded_columns": [
    "internal_id",
    "secret_note"
  ]
}
```

Using the existing widget fields means URL widgets automatically use the normal:

- Preview flow.
- Save Draft flow.
- Publish flow.
- Delete flow.
- Widget clone and dashboard clone flow.
- Builder reload and runtime dashboard flow.

No separate URL-widget storage mechanism was added.

## Runtime Flow

The runtime sequence is:

1. Load the published dashboard configuration.
2. Read the widget's `data_source`.
3. When the source is `url_json`, route only that widget to the URL JSON executor.
4. Validate the URL and request settings.
5. Fetch JSON using GET or POST.
6. Convert the JSON object or array into widget rows.
7. Remove excluded columns.
8. Return the rows to the existing KPI, Table, or Graph renderer.

PostgreSQL, SQL Server, and Hybrid widgets continue through their original branches in the query executor.

## Error Handling

The builder and runtime provide clear errors for:

- Missing API URL.
- Invalid URL.
- Protocols other than HTTP or HTTPS.
- URLs containing embedded username/password credentials.
- Unsupported request methods.
- Invalid POST JSON.
- DNS resolution failure.
- HTTP failure status.
- Invalid JSON response.
- Unsupported top-level JSON type.
- Request timeout.
- Response larger than the configured limit.
- Too many redirects.
- Unsafe localhost or private-network targets.

Errors are displayed through the existing widget preview/runtime error UI and do not crash Dashboard Builder.

## Security and Reliability

URL requests are executed by the backend so they are not blocked by browser CORS rules.

Protections include:

- HTTP/HTTPS only.
- GET/POST only.
- Eight-second timeout.
- Five-megabyte response limit.
- Maximum of three redirects.
- Validation of every redirect target.
- Blocking localhost, loopback, link-local, private, reserved, and unsafe IP ranges.
- Blocking embedded URL credentials.
- POST request bodies are retained for server-side execution but removed from public runtime widget responses.

Because private-network addresses are blocked, URL widgets are intended for APIs reachable through safe public HTTP/HTTPS addresses.

## Table Search Result Count

The shared Table renderer now shows a dynamic result count after a user enters a search:

```text
12 results found
```

Behavior:

- Hidden when the search field is empty.
- Updates while the user types.
- Uses the existing filtered row list.
- Shows correct singular text for one result.
- Does not modify the existing filtering logic.
- Works in builder previews, nested widgets, phone layouts, and live dashboards because they share the same Table renderer.

## Regression Safeguards

Additional safeguards added during the final review:

- Changing a data source clears stale preview/live rows.
- Switching from URL to Hybrid cannot reuse the URL as a PostgreSQL merge query.
- URL and Hybrid configuration changes are included in unsaved-change detection.
- URL widgets are validated before publishing or publishing a dashboard clone.
- Heterogeneous JSON rows use a stable union of keys.
- Sensitive POST bodies are not sent to normal dashboard viewers.

## Files Changed

### Frontend

`frontend/src/common/dashboard-builder/utils/dashboardDbSources.js`

- Adds the `URL` dropdown option.
- Adds `isUrlJsonDbSource`.

`frontend/src/common/dashboard-builder/services/dashboardApi.js`

- Sends URL preview configuration through the existing preview endpoint.
- Leaves the existing SQL Server request shape unchanged.

`frontend/src/common/dashboard-builder/components/PropertyPanel.js`

- Adds URL, method, POST body, and displayed-column controls.
- Adds frontend URL and JSON-body validation.
- Skips database table loading for URL widgets.
- Clears stale data when changing sources.

`frontend/src/common/dashboard-builder/components/DashboardBuilder.js`

- Persists URL method, body, and excluded columns.
- Passes URL configuration during preview and automatic builder reload previews.
- Includes URL and Hybrid settings in dirty-state tracking.

`frontend/src/common/dashboard-builder/components/WidgetRenderer.js`

- Removes excluded URL columns before rendering.
- Uses the union of keys from heterogeneous rows.
- Adds the dynamic Table search result count.

### Backend

`backend/src/apps/dashboard/lib/utils/query/urlJsonQuery.js`

- Contains the isolated URL request implementation.
- Validates URL, method, POST body, redirects, response size, timeout, JSON, and network target.
- Normalizes JSON into widget rows.
- Removes excluded columns.

`backend/src/apps/dashboard/lib/utils/query/queryExecutor.js`

- Adds one isolated `url_json` branch before the existing Hybrid, SQL Server, and PostgreSQL branches.

`backend/src/apps/dashboard/modules/dashboard/controllers/dashboard.controller.js`

- Allows `url_json` as a data source.
- Passes URL options to preview and runtime execution.
- Validates URL widgets before publishing.
- Removes POST bodies from public runtime responses.

`backend/src/apps/dashboard/lib/utils/schema/dashboardJsonSchema.js`

- Preserves URL method, body, and excluded columns through stored and runtime widget conversion.
