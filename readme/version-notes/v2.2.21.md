### Packing Entry — Stale item / qty shown after cancel

**Problem:**
- User creates a sticker → cancels → regenerates on the same doc no with a different item/qty.
- The screen still showed the previous item and quantity.

**Cause:**
- Cancel only deleted boxes; the old snapshot remained in `ims_dailyprod`.
- On reopen, the backend used that stale data.

**Fix:**
- On cancel, snapshot fields are cleared (row is not deleted): item, qty, customer, packing fields, audit — all set to NULL.
- `stickerFetchBox` now compares live packing-list data with DB history.
- After cancel, live data is preferred; stale `ims_dailyprod` is ignored when live data differs.

**Files:**
- `backend/src/apps/ims/models/box.model.js`
- `backend/src/apps/ims/controllers/box.controller.js`

### Scan — Incorrect "Already scanned" error (all IMS screens)

**Problem:**
- Immediately after a successful scan, the camera re-read the same QR → red "Already scanned" appeared.
- The box was not added; only a false error was shown.
- Same issue on Audit, Inward, Out Entry, QC Hold, and Sticker Override.

**Fix (4-second rule):**
- Same box within 4 seconds of success → silently ignored (camera re-read).
- Same box after 4 seconds → shows "Already scanned".
- Scan in progress → silently ignored.
- Real errors (wrong location, invalid QR) — unchanged red error behavior.

**Files:**
- `frontend/src/core/utils/scanSnackbar.js`
- `AuditExecutionModal.js`, `InwardModal.js`, `OutEntryModal.js`, `QcHoldMaterialModal.js`, `StickerOverrideModal.js`

### Web Push (PWA) — Delivery and device linking

**Added:**
- Task app can send browser push when the user is not on the page.
- Each device is linked to the logged-in user.
- Offline delivery: 7-day TTL.

**Delivery status:**
- `sent` → `received` (notification displayed) → `read` (user tap / inbox read)
- `sent` → `failed` (saved in error log)

**Logout behaviour:**
- Device link persists — push can still arrive after logout.
- When another user logs in, the device is re-linked to that user.

**Tables:** `mst_push_subscriptions`, `mst_push_delivery_log`

**Files:**
- Backend: `webPush.service.js`, `pushDeliveryLog.model.js`, `taskPwaPush.service.js`

### Analytics Dashboard — Builder, clone, publish, live view

**Overview:**
- Super Admin builds a dashboard per app (Home, IMS, Task, Settings).
- Data stored in PostgreSQL: `mst_dashboard_configs.dashboard_json`.
- Live users see only the published dashboard.

**Flow:**
- Build → `/settings/dashboard-builder` → add widgets, set layout, Save Draft.
- Publish → live dashboard visible to users.
- Unpublish → widgets hidden, welcome screen, filter bar also hidden.
- Clone → separate copy for specific users (auto-published).
- Live view → user-specific clone first, then global default.

**Widget visibility:**
- Backend checks audience + Page Access on every request.
- Super Admin sees all widgets.

**Date / user filters:**
- Shown only on published dashboard. Placeholders in widget SQL are replaced.

**Fixes in this release:**
- Published dashboard builder lock, drag block, clone panel overlap,
- filters after unpublish, home dashboard load — all fixed.

**Files:**
- Backend: `dashboard.controller.js`, `dashboardConfig.model.js`
- Frontend: `DashboardBuilder.js`, `dashboardApi.js`, `QuickAccessBar.js`, `home/page.js`
