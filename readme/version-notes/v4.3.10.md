### List footer — unified across apps

**Goal:** Same list-page footer behaviour everywhere (IMS, RM Store, Purchase, Production, Task, Settings, HRMS via shared list shells): count on the left, optional legend in the center, scope filter and row selection on the right.

**Import:**

```text
import AppListFooter, {
  ListPageFooterContextStrip,
  appListFooterFromClientFilter,
  consoleListSelectionLabel,
  ListFooterColorLegend,
} from "@/ui/common/list/listPageFooter";
```

| Zone | Content |
|------|---------|
| **Left** | `Showing X of Y {noun}`; optional hints (`Filtered From N`, journey `(all DB)`, quick-search narrowing via `appListFooterFromClientFilter`) |
| **Center** | `centerContent` or `extra` as React node — e.g. task status dots, recurring stat legend, schedule colours |
| **Right** | `ListPageFooterContextStrip` (stat / drill-down scope + clear) and/or `ListPageSelectionStrip` (selected row + **Clear row**) |

**Removed / consolidated:**

| Before | After |
|--------|--------|
| Per-app footer wrappers (`MasterListFooter`, `RmStoreListFooter`, etc.) | Single `AppListFooter` |
| Toolbar indigo “Selected: …” bars on many pages | Footer selection strip only |
| Separate **Live Database** footer text | No dedicated line; `databaseTotal` / `journeyMode` / `isFiltered` still drive inline count hints where pages pass them |

**Scope clear vs row clear:**

| Control | Clears |
|---------|--------|
| Scope strip **Clear** (filter icon) | List scope / stat filter (row selection can remain) |
| **Clear row** (pointer icon + X) | Table row selection only |

**Selection labels:** Domain helpers stay on pages — e.g. `imsSelectionLabel`, `rmStoreSelectionLabel`, `consoleListSelectionLabel` (Settings / Task admin), `buildTransactionLogFooterLabel` (coil / box logs).

**Shared list shells:** `ServerListPage` and `ClientListPage` render `AppListFooter` with the same props pattern as hand-built IMS pages.

### In-Process Request — Job Card / Machine on Pending

**Problem:** Pending shop-floor rows showed `—` for Job Card and Machine when the physical coil was not listed on the issue-request job card’s reserved `coils` JSON.

**Why:** Job-card Store Out can scan **any coil from the reserved MRN(s)**, not only the exact coil UIDs picked on the Issue Request. The old lookup matched only `jc.coils` by `coil_no_uid`.

**Example:** Issue Request reserves `…_SA20_1_1` for `JC-100`. Store Out scans `…_SA20_2_2` from the same MRN. Coil is on the floor with `out_uid` set, but Job Card / Machine were blank.

**Fix:** `COIL_JOB_CARD_JOIN` in `coil.model.js`:

| Priority | Source |
|----------|--------|
| 1 | Store Out row for `c.out_uid` → `pjobcardno`; machine from matching issue-request job card |
| 2 | Latest issue-request job card whose `coils` JSON lists this `coil_no_uid` |

Coil UID match is case-insensitive.

**Unchanged:** Rejection / non–job-card store-outs with no `pjobcardno` still show `—` (correct). Store Out and Issue Request screens already carry Job Card on their own rows.

### QR scanner — close on phone (shared overlay)

**Where:** `QrScannerOverlay.js` — used with `useHtml5QrScanner` across RM Store, IMS, audits, finders, Gate Entry, etc.

**Problem:** On phone, **Close (X)** often did nothing; **torch** still worked.

**Causes:**

| Issue | Fix |
|-------|-----|
| Overlay marked `inert` while a drawer/modal was open | `data-qr-scanner-overlay="true"`; skip in `overlayFocusGuard.js` |
| Close fired on `pointerDown` (mobile ghost-tap / pass-through) | Close on **click** only; `pointerDown` stops propagation (same pattern as torch) |
| Camera DOM capturing taps | Toolbar `z-index`; 44×44px targets; `pointer-events-none` on html5-qrcode children inside the reader |

**Also:** Short debounce on close to avoid double-fire; ESC still closes via `useEscapeKey`.

### Gate Entry — scan and bill number

**Where:** `GateEntryModal.js`, `gateEntry.js`, `qrScan.js` (helpers), backend `gateEntry.controller.js` (`buildOpenPayload`).

#### Bill number display (casing)

| Input | Display after load |
|-------|-------------------|
| User types `hpf/26-27/2305` | IMS value, e.g. `HPF/26-27/2305` |
| QR / laser with doc number | Same — canonical from `invmnote` / `invfnote` |

Backend: after case-insensitive IMS match, `bill_no` in open-bill response uses `canonicalBillFromIms`. Frontend `applyPayload` prefers `invmnote.billno`.

#### Open-bill request (`gateEntry.js`)

| Scan / type | API body |
|-------------|----------|
| Digits only (e.g. `2305`) | `bill_no`: `HPF/{FY}/{number}` (selected financial year required) |
| Plain bill (e.g. `HPF/26-27/2305`) | `bill_no` — not sent as encoded QR |
| E-invoice JWT, base64 blob, or JSON QR | `qrData` — parsed on **backend** (`parseBillScanPayload`) |
| Other typed text | `bill_no` |

No client-side JWT decode in the service layer (keeps one parser on the server).

#### Phone camera (Gate Entry → New)

| Item | Detail |
|------|--------|
| QR button | `showPhoneQr` on mobile when Phone QR is enabled in device settings; desktop webcam when Phone QR is on (bill scan at gate PC) |
| Incomplete QR | `billQrCameraLooksIncomplete` — blocks only obvious partial JWT/base64 (not laser idle rules) |
| Scan region | Dynamic `qrbox` (~88% of viewfinder) via `useHtml5QrScanner` |
| Failed load after scan | Camera reopens so user can scan again |
| Helpers | `looksLikePlainGateBillNo`, stricter `looksLikeBillBase64` (length ≥ 48; plain bills excluded) |

**Unchanged:** Gate Entry save/update, pending list, and register list logic. Invoice Receiving is a separate module.

### RM Inventory Report — query performance

**File:** `backend/src/apps/rmstore/modules/inventory-report/models/inventoryReport.model.js`

**Goal:** Keep report logic the same; make data load faster after adding location hover coils.

| Before (slow) | After |
|---------------|--------|
| Correlated location subquery **per MRN** | Location chips + rack UID map built **once** (`loc_parts` / `loc_by_mrn`) then joined |
| Extra full map for UA/SF/QC | Map only for **racks**; UA/SF/QC hover uses `unassigned_coil_uids` / `shop_floor_coil_uids` / `pending_qc_coil_uids` |
| QC join on every location bucket | QC join only where **PENDING_QC** needs it |
| Heavy `STRING_AGG(DISTINCT … ORDER BY)` on UIDs | Plain `STRING_AGG` (same coils; order may differ slightly in tooltips) |
| Consumed coils scanned | Early skip `status <> 'consumed'` (they never count in buckets) |

**Unchanged:** In Store / Unassigned / Shop Floor / Issuable / QC Pending / RM Rejection qty rules; location chip text (`2C (3), UA (1), SF (2), …`); frontend UA/SF badges + tooltips.

**Smoke test:** Open Inventory Report → load time · hover rack / UA / SF · qty cards match prior.

### RM Store — Quick Search vs DB filters

**Rule (all list pages):**

| Control | Behaviour |
|---------|-----------|
| **Quick Search** (indigo field) | Debounced type → filter **already loaded** rows (`applyClientSearch`) |
| **Dates / status / server dropdowns** | Change alone does **not** refetch; commit on **Search** or **Enter** (`applyExtrasOnChange={false}`) |

**Fixes:**

| Page | Change |
|------|--------|
| `out-entry/Page.js` | Pending tab: client quick search (was Store Out only) |
| `rm-rejection/Page.js` | Pending tab: client quick search |
| `in-process-request/Page.js` | Pending: `quickSearchOnly`; Register: Enter applies server filters |
| `inventory-audit/Page.js` | Explicit `searchVariant="quick"`, `applyExtrasOnChange={false}`, Enter = Search |
| `stock-adjustment/Page.js` | Enter = Search for dates/status |
| Masters (location / rm-spec / production) | Enter = Search for status |

**Already correct (no change needed):** Coil, Issue Request, Inventory Inward, QC Check, MRN Portal, Coil TX / Sticker logs (`applyExtrasOnChange={false}`).
