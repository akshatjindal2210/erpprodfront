### Store Out — Inventory Out: optional item stock info

**Problem:**
- On Inventory Out, users typed or scanned `box_no_uid` with no preview of in-stock boxes for an item (packing, qty, full/loose, location).

**Cause:**
- The form had only Reason → scan/ADD. Items helper did not allow the `out_entry` page.

**Fix:**
- Optional **Item** picker after Reason (information only — not required to ADD or submit).
- Selecting an item shows in-stock boxes grouped by packing (expand/collapse, Expand all / Collapse all).
- New API: `POST /out-entries/available-boxes`. Allowed `out_entry` on `/master/items/helper`.
- `item_dcode` is not sent on create/update.

**Flow:**
1. Inventory Out → enter reason
2. *(Optional)* select item → view stock by packing
3. Type/scan `box_no_uid` → ADD → submit (**PENDING**)

**Files:**
- `backend/src/apps/ims/config/helperViews.js` — allow `out_entry` on items helper
- `backend/src/apps/ims/controllers/outEntry.controller.js` — available boxes by item
- `backend/src/apps/ims/routes/outEntry.route.js` — `POST /available-boxes`

- `frontend/src/features/apps/ims/config/endpoints.js` — `AVAILABLE_BOXES`

### Store Out — Inventory Out: pending submit + special approve

**Problem:**
- Inventory Out was authorized and stock reduced on submit.
- Inventory approve needed its own permission (not `out_entry` authorize).
- Edit after approve showed Qty: 0; sticker scans sometimes stored raw text instead of `box_no_uid`.

**Cause:**
- Inventory Out was auto-authorized. Linked-boxes query missed `qty`. Batch scan did not always resolve to canonical `box_no_uid`.

**Fix:**
- Submit → **PENDING**; stock updates only after **Inventory Approve** (`ims.inventory_approve`).
- Create still needs **Inventory Out** (`ims.inventory_out`). FN Out still uses `out_entry` authorize.
- Approve UI on Store Out and Pending FN tabs; Keep Pending / Approve in modal.
- Fixed linked-box qty and sticker → `box_no_uid` resolve.

**Flow:**
1. Inventory Out user → scan + submit → **PENDING**
2. Inventory Approve user → **Approve** → stock out
3. FN Out → Approve with `out_entry` authorize

**Problem:**

### Forwarding Note — Today's Dispatch Plan: Complete confirmation

**Problem:**
- Clicking **Complete** on Today's Dispatch Plan marked the item complete immediately, with no confirmation step.

**Cause:**
- Complete called the API directly from the toolbar; Reject/Reschedule already used drawers, Complete did not.

**Fix:**
- **Complete** opens a confirmation drawer (item details + confirm message). No reason field.
- **Confirm Complete** or **Ctrl+S** submits; **Esc** / Cancel closes.
- **Reschedule** drawer also supports **Ctrl+S** (target date still required).
- Button labels stay simple (no Ctrl+S badge on the button).

**Flow:**
1. Select planned row → **Complete**
2. Review item → **Confirm Complete** (or Ctrl+S)
3. Item marked complete; list refreshes

**Files:**
- `frontend/src/features/apps/ims/components/forwarding-note/DispatchCompleteModal.js` — **new** confirmation drawer
- `frontend/src/features/apps/ims/components/forwarding-note/TodayDispatchPlanTab.js` — open complete drawer instead of direct API call
- `frontend/src/features/apps/ims/components/forwarding-note/DispatchRescheduleModal.js` — Ctrl+S via Drawer `onSubmit`
