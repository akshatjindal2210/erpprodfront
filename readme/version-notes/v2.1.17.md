
## v2.1.17

### Dashboard — Empty gap for hidden widgets in live view

**Problem:**
- Widgets the user could not access were hidden, but their grid positions remained empty.
- White space appeared in the middle of the screen; lower sections did not shift upward.

**Cause:**
- The backend returns only allowed widgets.
- The frontend rendered them at their original x/y positions, leaving empty rows where hidden widgets had been.

**Fix:**
- On the live dashboard (read-only), visible widgets are now vertically compacted.
- `compactLayoutVertically()` no longer leaves gaps for hidden widgets.
- Builder and Super Admin views are unchanged.

**File:** `frontend/src/features/dashboard-builder/components/DashboardBuilder.js`

---

### Schedule Planning — Incorrect filters on default report

**Problem:**
- On the default report, month/date fields were disabled, but `fromDate`, `toDate`, and `month` were still sent to the API.
- This could return incorrect data.

**Fix:**
- Default report: the UI shows the current month; date fields remain blank.
- The API receives only `reportType` and `status`.
- The backend sends the current month to IMS (`requestedData: "schdule"`).
- Custom report: only the month/date selected by the user is sent.

**Files:** `schedule-planning/Page.js`, `schedulePlanService.js`

### Store Out — Draft save succeeds, submit shows access error

**Problem:**
- Users could scan boxes and save a draft, but on return, submit showed "no access".
- Admins had not changed permissions — this was introduced by a code change.

**Cause:**
1. `fieldsForForwardingNotes` allowed only view; the Store Out form requires add/edit.
2. Draft save uses the create API (Add permission). Submit uses the update API — only Edit was previously allowed.

**Fix:**
- `fieldsForForwardingNotes` — allow view, add, edit, and authorize for `out_entry` and `forwarding_note_master`.
- `outEntry.route.js` — allow add on the update route so users can complete their own draft.

**Files:** `helperViews.js`, `outEntry.route.js`
